# Java 分析验收报告

正式组件 `pyxis-java-analysis` 提供 Java 17 分析、Mod 会话装配、引用增量刷新与共享 JVM。JDT Core 为 3.47.0，自有宿主为 1.0.0，通信协议为 2。

## 组件管理

设置页在配置文件与性能调试之间装配 Java 分析卡片，提供固定依赖下载、取消、重试、离线导入、检查修复、移除、Java 路径、自检及停止分析。网络实现归组件，后台 FIFO 队列拥有当前动作、待执行项、取消控制与完成回执；相同动作复用原队列项，命令等待所属回执，状态订阅独立交付当前进度。应用关闭先清空待执行项并取消、等待当前项，再释放分析运行态。

实际固定清单包含 27 个 JAR、16,423,216 字节，逐文件流式校验；有效暂存用于重试，完整清单验证后登记安装。Java 17 自检解析中性小样本后释放独立 JVM、读取线程和工作区。手动 Java 路径验证后进入 AppSettings 保存及镜像，移除保留路径设置与日志。

管理验收的完整命令、截图、资源释放、性能及产物哈希见 [管理验收](../../.zcode/plans/java-ast-engine/STAGE10-REPORT.md)。当前主项目 Rust 测试为 741 项通过，前端为 298 个文件、3,797 项通过，Clippy、typecheck、ESLint、工程规则和 Tauri 无安装包构建通过。

## 现有入口与寿命

- `inputs_for_session` 取得当前就绪 Mod、已发布可引用 Mod、游戏 Core、标准库及显式补充来源，返回缺失依赖、缺失 JAR 和文件指纹。
- `start_for_session(app, session_id, java, extras)` 显式建立项目，已有分析项目共用 JVM；`request_for_session` 核对项目身份与版本，`close_for_session` 释放单项目，最后项目关闭后 JVM 退出。
- 引用仍由工作区自动或手动选择，经现有发布链交付后端；已发布的全部可引用 Mod 按标签顺序提供源码和 JAR，前后标签均可参与。
- 项目同步在 Mod 注销前释放所属 Java 项目，引用发布后自动刷新存活分析项目，当前内存文档和版本继续保留。应用关闭统一等待进程、读取线程及工作区释放。
- 本轮自建测试夹具使用中性 Mod ID、目录、类型和源码，三个指定真实 Mod 使用显式外部目录，只读核对指纹。

## 增量语义与输入到运行证明

每文件保存声明签名、使用名称、绑定键、紧凑语义事实、诊断及引用位置。方法体保持签名时只失效该文件；签名、常量、导入和类型变化沿保守名称依赖闭包传播。JAR 按 SHA-256 及有效版本 class 条目比较，配置变化只失效使用变化类型的源码。语言或标准库变化记录完整回退原因。

语义事实在 JDT 交付 AST 的回调内固化，紧凑绑定记录按值复用，引用位置按文件增量替换；查询读取所属版本事实。不同 JVM 使用各自请求锁，运行态锁只保护登记；共享 JVM 的单管道顺序执行。响应记录等待、请求耗时和字节数，分析结果记录重解析数量、失效数量、耗时及回退原因。

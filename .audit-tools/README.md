# 本地架构事实审计

本工程从项目现行文档和实际文件提取依赖、声明与源码位置，推断模块归属并生成可追溯报告。
源码、测试、配置及依赖锁文件由 Git 管理，依赖安装目录、运行环境、生成报告和浏览器缓存由主仓库的 `.gitignore` 忽略。

## 环境与命令

本工程是主仓库的 npm workspace，Node.js 环境、TypeScript、Node 类型与 Playwright 由根 `package.json` 和唯一的根 `package-lock.json` 管理，安装入口为根目录 `npm ci`。
类型配置继承主仓库 `tsconfig.browser-scripts.json` 及其严格基础，源码和测试共同检查；Emscripten 类型提供 WASM 依赖的宿主声明。格式与 ESLint 消费主仓库配置，根 `typecheck`、`lint` 和 `lint:full` 覆盖本工程。
原生环境沿用项目 Rust 工具链及 Windows MSVC 构建工具。
Graphify 环境使用 Python 3.12。所有命令均可从任意工作目录调用。

```powershell
.audit-tools/audit.cmd setup
.audit-tools/audit.cmd scan
.audit-tools/audit.cmd scan --baseline
.audit-tools/audit.cmd view
.audit-tools/audit.cmd check
.audit-tools/audit.cmd clean-runtime --dry-run
.audit-tools/audit.cmd clean-runtime
.audit-tools/audit.cmd clean-reports --dry-run
.audit-tools/audit.cmd clean-reports
```

`setup --graphify` 安装可选的 Graphify 环境，`scan --graphify` 将其提取与聚类结果加入报告。
`setup --dry-run` 和 `scan --dry-run` 展示执行配置。
`scan --baseline` 使用相同引擎，将基线完整报告保存到 `output/baseline/`。
`scan --baseline --replay-baseline` 从已有基线的文件快照及原始引擎输出重新分析，记录复用来源及当前工具身份；本次分析使用保存的输入身份。
`view` 在 `http://127.0.0.1:8766/` 提供最新成功报告。
没有已发布报告时，页面显示扫描状态并提供手动生成入口；扫描进行中或失败时，已有成功报告继续可读。

前端语义引擎使用主仓库 TypeScript、@vue/language-core 3.3.13 和 @volar/typescript 2.4.28；dependency-cruiser 18.6.0 解析资源关系。Rust 语义引擎为 rust-analyzer 0.3.3105，2026-11-02 发行包，SHA-256 固定。
前端引用及调用签名消费官方 checker；Vue 模板和生成声明消费官方源码映射；Rust 位置消费 tree-sitter-rust 0.24.2 的官方 WASM，发行文件 SHA-256 固定。
Rust 名称、类型、绑定、调用、字段与导入目标统一消费 rust-analyzer LSIF；源码语法树只维护位置、条件、装配、协议和项目规范，模块关系及可视布局由后处理交付。
Graphify 0.9.90 提供探索聚类。
依赖版本由 package lock 和 Graphify requirements lock 固定。

## 数据与证据

- 输入为 Git 登记与未忽略的当前文件，范围与哈希在扫描前后核对。
- 模块来自现行模块索引和所属文档，文档引用保留原始位置及职责文字。
- 参考直接读取“拥有、消费、装配、关联”分组，职责备注及行号作为证据保留。
- 公共文件由 shared 目录及模块索引的公共文件清单确定，共址测试继承公共属性，模块归属为空。
- 业务文件归属分为声明所属、引用候选、声明冲突和未覆盖；唯一拥有声明产生正式所属。
- 拥有目录覆盖全部后代；共址测试继承对应生产入口的拥有依据，Rust 测试优先保留声明及配对归属，沿 `mod` 与 `#[path]` 父链补齐归属并保留声明位置及冲突证据。
- 消费、装配、关联及实际消费者保留各自证据，正式模块依赖只连接已声明所属的业务文件，公共文件单独列出。
- 依赖保存种类、端点、符号身份、来源位置及提取方式，Rust 关系分类为实际使用、结构引用及定位待核。
- TypeScript 与 Vue 官方语言工具必须作为前端代码语义目标的唯一权威；脚本只允许消费声明、签名及源码映射，严禁按名称推断或覆盖实际目标。
- 前端项目必须按现行 tsconfig 的实际根装配分别执行；仅包含编译选项的继承配置必须归配置基础，配置外文件必须保留全部原始位置及具体缺口。
- 前端模块引用必须保留实际导出入口，能力使用必须保留最终声明；索引类型及函数参数必须按契约交付，严禁表述为唯一运行时实现。
- 全局环境声明和模块扩展必须按官方声明作用域交付结构契约；全局组件的 `typeof` 来源必须消费官方符号声明，实际组件使用必须保留所属实现关系。
- 前端语言内建身份、声明、生成位置、类型契约及定位缺口必须分别计量；原始引用位置必须随引擎结果保存。
- 元组标签及 JSDoc 参数名必须按语法分类；解构来源键必须消费来源类型，合成属性必须保留官方类型契约及值类型，严禁将契约声明表述为逐键定义。
- Vue 动态指令参数的源码位置必须包含参数外围符号的实际偏移，引用片段必须对应原始标识符。
- 前端资源关系必须独立记录物理端点及来源，dependency-cruiser 严禁生产代码语义目标。
- IPC 和事件协议必须消费已定位的正式声明身份与参数传递证据；同名局部函数必须保留其独立身份。
- rust-analyzer 必须作为全部 Rust 语义目标的唯一权威，严禁脚本覆盖或并行推断其已定位的声明；引擎缺口的调查补充必须独立标注依据。
- 模块声明、命名空间与可见范围必须归结构关系；局部变量和字段简写必须保留引擎给出的完整角色；源码条件和项目拥有关系只参与后处理。
- Rust 业务边界按唯一直接拥有关系判定；跨业务类型必须具名导入，业务重导出必须直达声明，通配出口和中间转导出进入待核问题。
- 多个 Cargo manifest 发现的同一 Rust target 必须按实际源入口归并后进入正式引用分析。
- 引用保留实际引用与声明位置、转导出路径、条件编译及测试作用域；语义符号与关系来自同次 LSIF，并与原始索引共同保存。
- 字段、trait 分派与生成能力必须保留所属声明或展开来源，严禁将分派契约表述为唯一运行时实现。
- 语义引擎及其原始索引必须随扫描保存；引擎失败严禁发布报告，基线重放必须消费同次原始索引。
- 语义解析增补必须在冻结的未审计清单上覆盖至少 20%；计量必须交付原始位置、目标声明及输入身份。
- 目标歧义、未解析的项目引用、方法接收者及宏展开进入覆盖问题，已知候选提供源码位置。
- 状态与函数页面展示静态声明和作用域；生命周期线索按源码证据呈现。
- 语义覆盖必须区分未定位与编译器条件未启用的位置；生命周期、属性名称及元组数字位置必须按语法角色统计，严禁计作未解析依赖。
- 辅助语法树必须支持项目 Rust edition；父模块条件必须覆盖嵌套外部声明及其后的测试函数，语法诊断必须保留实际位置。
- 覆盖问题登记解析、引用、条件编译和符号定位缺口，Graphify 保留其探索结果属性。
- 生产归属覆盖交付正式拥有、公共文件、未覆盖文件及受影响关系的实际数量；Rust 文件范围消费父模块与文件条件编译，引用、事件和嵌入资产保留所属测试范围。
- 命令关系消费正式 command 宏与 handler 登记；生产调用必须匹配生产登记，测试登记必须保留测试依据。

分析输入只允许来自项目现行文档和实际文件。
归属候选、模块列表和审计结论严禁通过人工配置输入。
静态声明数量严禁作为状态归属或生命周期正确性的证明。
人工任务记录必须保存在 `.zcode/plans/`。

## 目录与生命周期

| 位置                     | 职责                                   |
| ------------------------ | -------------------------------------- |
| `src/`                   | 命令、采集、推断、运行生命周期和报告   |
| `test/`                  | 解析、协议、归属、发布及真实浏览器测试 |
| `../node_modules/`       | 主仓库 npm workspace 管理的共同依赖    |
| `.runtime/tools/`        | Rust 分析引擎                          |
| `.runtime/python/`       | 可选 Python 环境                       |
| `.runtime/browsers/`     | 浏览器测试环境                         |
| `.runtime/cache/`        | 下载与外部引擎缓存                     |
| `.runtime/build/`        | Rust 构建产物                          |
| `.runtime/work/`         | 活动任务中间文件                       |
| `.runtime/logs/`         | 安装、检查和按扫描编号隔离的失败诊断   |
| `.runtime/last-run.json` | 最近扫描的终结结果                     |
| `output/current.json`    | 当前成功扫描目录指针                   |
| `output/scan-*/`         | 最新成功扫描的完整机器产物             |

扫描必须串行执行到终结。
发布必须在所选引擎完成、结果校验通过及输入哈希一致后执行。
扫描失败必须保留上一份成功结果。
运行环境清理必须使用 `clean-runtime`，只允许操作工具拥有的缓存、构建和临时目录。
报告清理必须使用 `clean-reports`，默认必须逐文件删除 `output/` 中的报告和 `.runtime/last-run.json` 并保留目录。
报告清理带 `--dry-run` 时只允许列出待删除路径、文件数和字节数。
报告清理必须与扫描及安装共用操作锁。

## 报告与验证

报告包含模块图、文件图、Rust 图、可选聚类图、归属证据、上下游、循环和待核线索。
默认口径为实际能力依赖，Rust 采用可确定目标的实际使用；完整引用关系同时展示结构引用和定位待核证据。
关系范围默认展示源码依赖；通信关系包含 IPC 与窗口事件，组合关系共同展示两类证据。
源码循环与通信闭环分别标识；组合图内包含源码循环的成员组标识为源码循环。
图形与循环共同消费当前口径、视图、范围及关系筛选；循环提供成员、闭合链路和对应证据。
节点检索及局部上下游用于浏览，循环按筛选后的完整图计算，同文件引用保留在证据中。
模块节点坐标由 Dagre 1.1.8 按有向依赖计算，基础节点位于下方，循环关系保留原始节点与连线。初始视图采用可读比例，完整全图与 100% 比例分别提供操作入口，文件与线索面板按需展开。
HTML 内嵌图形库、样式与脚本；概览、关系索引、文件详情和待核线索由本机服务按报告编号分开读取。完整 JSON、CSV、DOT 保留为同源下载。
`ownership.csv` 导出所属与全部候选证据；`dependencies.*` 导出文件关系。
`module-dependencies.*` 导出正式模块依赖及对应文件端点。
上述依赖 CSV、DOT 为完整引用关系，`dependencies-usage.*` 与 `module-dependencies-usage.*` 为实际能力依赖。
上述文件包含组合关系；文件名中的 `-source` 与 `-communication` 分别导出源码和通信范围，各范围提供完整引用与 `-usage` 实际能力口径。JSON 数据协议为版本 5，概览协议为版本 2，循环记录包含关系范围与分类。
CSV 记录关系分类、符号身份、引用及声明行列和完整证据；所有导出覆盖全部维护文件范围。
归属状态筛选在当前文件范围中按 100 条分页，证据面板按需展示关系与源码位置。待核线索按类别汇总，详情按每页 100 条读取。
源码查看使用扫描时的内容，哈希标识对应输入身份。报告 API 必须携带当前报告编号，版本替换后必须交付更新状态。

`check` 执行格式、完整 ESLint、源码及测试的 JSDoc 类型、单元、集成和 Chromium 浏览器检查。格式化使用主仓库安装的 Prettier、根 `.prettierrc` 和 `.prettierignore`，运行产物由根 `.gitignore` 管理。
浏览器检查消费最新成功报告，并验证图形、检索、源码、亮暗主题、窄窗口和焦点。
检查日志及截图位于 `.runtime/logs/check/`。

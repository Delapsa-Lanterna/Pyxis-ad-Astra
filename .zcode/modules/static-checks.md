# 静态检查系统

## 定义

静态检查系统验证仓库结构、源码职责、文本格式与模块契约。

## 参考

### 拥有

- `.gitattributes`：维护文本与换行属性。
- `.github/`：装配与本地相同的完整验证命令。
- `.gitignore`：维护产物忽略范围。
- `.prettierignore`：维护格式化范围。
- `.prettierrc`：维护统一格式。
- `.zcode/module-map.md`：维护公共文件、模块索引和文档契约。
- `.zcodeignore`：维护上下文排除范围。
- `eslint.config.js`：维护 ESLint 的源码范围与写法约束。
- `eslint.full.config.js`：消费共同配置交付完整 ESLint 检查入口。
- `rustfmt.toml`：维护 Rust 格式。
- `scripts/architecture/check.mjs`：按固定注册清单执行规则并排序诊断。
- `scripts/architecture/diagnostics.mjs`：维护统一诊断契约。
- `scripts/architecture/facts/`：建立源码、路径、角色、关系与文档事实。
- `scripts/architecture/registry.mjs`：登记规则、依据与实现来源。
- `scripts/architecture/rules/`：按依赖、能力、写法、业务、文档及规则自身职责组织检查。
- `scripts/architecture/testing/`：维护检查器测试共用的源码与模块文档夹具。
- `scripts/check-architecture.mjs`：采集事实、执行检查并交付退出码。
- `scripts/check-encoding.mjs`：检查 UTF-8 无 BOM 文本。
- `scripts/check-frontend-imports.mjs`：检查前端内联类型导入及字符串 mock 的模块来源。
- `scripts/check-identifier-length.mjs`：检查变量与函数长度。
- `scripts/check-imports.mjs`：统一扫描前端与 Rust 源码并交付导入检查结果。
- `scripts/check-rust-imports.mjs`：检查 Rust 跨模块顶部导入及使用点模块路径。
- `scripts/check-rust-module-boundaries.mjs`：检查业务模块转导出来源、层数与跨模块类型导入。
- `scripts/check-styles.mjs`：检查展示依赖、语法、声明与变量来源。
- `scripts/check-text-guidelines.mjs`：可见文字来源、标点与间距检查入口。
- `scripts/test-rust-paths.ps1`：验证 Windows 长路径与实际 8.3 短路径。
- `scripts/test-rust.mjs`：Rust 测试运行、能力探测、工作区释放及结果记录。
- `scripts/types/`：维护检查依赖的类型声明。

### 消费

- `scripts/shared/files.mjs`：提供统一仓库遍历与路径清单。
- `scripts/shared/frontend-source.mjs`：提供 Vue 脚本、绑定、调用与语法树。
- `scripts/shared/rust-source.mjs`：提供保留位置的 Rust 生产源码视图。
- `scripts/shared/source-position.mjs`：提供原始偏移对应的行列位置。
- `scripts/shared/style-source.mjs`：提供展示语法与依赖事实的检查。

## 边界

- File History 证明变更来自 WriteResult、回放操作归属及文本回放事件归属。
- ReadTicket 直接消费者按正式实现提取工厂、接纳、撤销与完成值角色，逐路径核对结果发布和释放。
- 公共采集与语言解析按实际共同消费者维护。
- 执行顺序、取消、接纳与释放由所属行为测试证明。
- 架构专用角色、关系与授权声明归静态检查系统。
- 每项业务职责的声明、判断与测试就近维护。
- 源码职责依据实际调用、绑定、导出与消费关系判断。
- 编码、格式、展示、架构与标识符检查分别拥有正式入口。
- 规则消费统一事实及正式声明。
- 文件归属覆盖正式源码、资产和工程入口，同名测试继承实现的业务归属或公共属性。
- 跨模块依赖按实际定义来源逐边匹配所属模块的消费入口声明。
- 路径边界规则复用 Rust 调用、函数及导入别名事实，同时采集公共测试计数器的辅助函数。
- 函数能力沿实际绑定、局部调用、导出来源与运行时装配依赖传播，领域和解析规则消费纯计算，查询消费只读操作。

## 链路

### 建立事实

1. 公共收集器交付完整文件与目录身份。
2. 架构采集读取适用源码、配置、资产与模块文档。
3. 前端解析保留绑定、类型属性、实际来源、作用域与原始位置。
4. Rust 解析交付生产引用、别名、导出、函数与位置。
5. 文档解析交付章节、参考、索引与公共文件关系。
6. 检查上下文只读交付事实及所属索引。

### 检查与诊断

1. 来源解析定位项目内部依赖。
2. 依赖判断依次消费层级、业务关系与能力授权。
3. 业务规则验证所属长期职责。
4. 文档结构与归属分别消费同一解析结果。
5. 规则自身检查消费固定注册清单。
6. 诊断按文件、位置和规则编号排序并交付退出码。

### 本地与持续集成

1. lint 执行共同基础及 Vue 检查，lint:fix 在同一范围执行工具支持的自动修复。
2. lint:full 复用共同配置并消费各运行环境的类型信息完成异步与分支检查。
3. Node 测试发现 scripts 下全部共址检查测试。
4. 架构入口对真实仓库执行全部正式规则。
5. 展示与标识符入口完成所属检查。
6. typecheck 依次检查应用、单元测试、Vite 配置、工程脚本、浏览器脚本、桌面脚本与审计工具。

## 规范

- CI 的 Rust 全测必须分别在长路径与实际 8.3 短路径的独立进程执行。
- CI 必须实际执行超过 260 字符的路径场景；本地能力不足交付未执行清单及验证不完整结果。
- 测试工作区必须排他创建并持有所属文件寿命；失败清理保留原始测试错误、实际路径和释放错误。
- Rust 测试必须经统一运行入口交付命令退出码、环境能力、未执行场景、工作区释放及实际报告路径。
- 公共文件与共址测试必须保持公共属性，模块拥有声明严禁覆盖公共文件。
- 前端运行时与类型依赖必须共同参与循环及层级检查。
- 模块依赖检查必须按正式归属合并前端与 Rust 生产导入及嵌入资产，追踪实际出口，并以闭合链路和逐边源码位置报告双向与多模块循环。
- 内联类型导入检查必须覆盖 TypeScript、Vue 脚本和测试中的类型语法，并按原始源码位置报告；JSDoc 按注释语义处理。
- Rust 导入检查必须覆盖生产与测试源码，核对使用点模块路径、局部导入及模块定义后的私有导入，并保留原始位置、条件属性、类型关联项与宏展开语义。
- 各类源码、文档、导出索引与角色必须在单次执行中建立并复用。
- 新增约束必须覆盖合法与触发输入，断言验证编号、位置、证据与期望职责。
- 每个 `.check.mjs` 必须以对应实现为主要测试对象，与实现同目录、同主文件名；整体规则调度与命令执行分别归所属入口测试。
- 直接由 Node 执行的工程脚本必须采用 NodeNext 解析，Vite 装配采用 Bundler 解析。
- 应用、单元测试、Vite 配置、工程脚本、浏览器脚本与桌面脚本必须分别消费所属运行环境的类型配置。
- 跨环境消费的 JavaScript 实现必须通过源码 JSDoc 交付类型，严禁使用同名声明文件覆盖实现推导。
- 展示静态检查必须排除路径段为 test 的目录内源码；正式展示依赖检查严禁消费测试目录中的定义。
- 规则必须登记稳定编号、现行依据和实现来源。
- 内部函数职责必须按实际声明、绑定和调用确定，外部能力按已解析的标准库与依赖接口识别。
- 票据结果发布必须在每条有效路径经过同一票据的接纳检查，后续等待重新建立接纳权，释放回调的全部退出路径完成撤销。
- 规则编号必须唯一，契约章节、能力提供者与消费者职责必须对应实际声明，同名检查测试必须进入正式发现范围。
- 路径边界检查必须覆盖展开入口归属、磁盘身份比较及原始 Path 经局部赋值进入字符串键的调用，诊断交付实际位置、对象及正式入口。
- 路径身份的 Unicode 大小写转换必须由公共 Windows 能力维护，静态检查覆盖散写的大小写转换。
- 计划工作区必须保留在路径清单，并且严禁进入架构与展示源码解析。
- 诊断必须携带规则编号、文件、行、列与原因，关系诊断携带实际目标或符号及期望职责。
- 转导出与整模块引用必须保留表面入口及原始定义来源。
- 显式 JavaScript 扩展名的来源解析必须按 TypeScript 扩展名替换顺序识别对应源码与声明。

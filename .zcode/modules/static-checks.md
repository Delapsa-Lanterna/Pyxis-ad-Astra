# 静态检查系统

## 定义

静态检查系统验证仓库结构、源码职责、文本格式与模块契约。

## 参考

### 拥有

- `.gitattributes`：维护文本与换行属性。
- `.github/`：装配与本地相同的完整验证命令。
- `.gitignore`：维护产物忽略范围。
- `.prettierignore`：维护格式化范围。
- `.prettierrc`：维护统一格式。
- `.zcode/module-map.md`：维护公共文件、模块索引和文档契约。
- `.zcodeignore`：维护上下文排除范围。
- `eslint.config.js`：维护 ESLint 的源码范围与写法约束。
- `eslint.full.config.js`：必须消费共同配置交付完整 ESLint 检查入口。
- `rustfmt.toml`：维护 Rust 格式。
- `scripts/architecture/check.mjs`：按固定注册清单执行规则并排序诊断。
- `scripts/architecture/diagnostics.mjs`：维护统一诊断契约。
- `scripts/architecture/facts/`：建立源码、路径、角色、关系与文档事实。
- `scripts/architecture/registry.mjs`：登记规则、依据与实现来源。
- `scripts/architecture/rules/`：按依赖、能力、写法、业务、文档及规则自身职责组织检查。
- `scripts/architecture/testing/`：维护公共夹具与跨规则验收。
- `scripts/check-architecture.mjs`：采集事实、执行检查并交付退出码。
- `scripts/check-encoding.mjs`：检查 UTF-8 无 BOM 文本。
- `scripts/check-identifier-length.mjs`：检查变量与函数长度。
- `scripts/check-styles.mjs`：检查展示依赖、语法、声明与变量来源。
- `scripts/test-rust-paths.ps1`：验证 Windows 长路径与实际 8.3 短路径。
- `scripts/test-rust.mjs`：Rust 测试运行、能力探测、工作区释放及结果记录。
- `scripts/types/`：维护检查依赖的类型声明。

### 消费

- `scripts/shared/files.mjs`：提供统一仓库遍历与路径清单。
- `scripts/shared/frontend-source.mjs`：提供 Vue 脚本、绑定、调用与语法树。
- `scripts/shared/rust-source.mjs`：提供保留位置的 Rust 生产源码视图。
- `scripts/shared/source-position.mjs`：提供原始偏移对应的行列位置。
- `scripts/shared/style-source.mjs`：提供展示语法与依赖事实的检查。

## 边界

- File History 必须证明变更来自 WriteResult、回放操作归属及文本回放事件归属。
- ReadTicket 直接消费者必须证明结果接纳与释放失效，生命周期事实由共享前端解析消费。
- 公共采集与语言解析按实际共同消费者维护。
- 执行顺序、取消、接纳与释放由所属行为测试证明。
- 架构专用角色、关系与授权声明归静态检查系统。
- 每项业务职责的声明、判断与测试就近维护。
- 源码职责依据实际调用、绑定、导出与消费关系判断。
- 编码、格式、展示、架构与标识符检查分别拥有正式入口。
- 规则消费统一事实及正式声明。
- 路径边界规则复用 Rust 调用、函数及导入别名事实，同时采集公共测试计数器的辅助函数。

## 链路

### 建立事实

1. 公共收集器交付完整文件与目录身份。
2. 架构采集读取适用源码、配置、资产与模块文档。
3. 前端解析保留绑定、类型属性、实际来源、作用域与原始位置。
4. Rust 解析交付生产引用、别名、导出、函数与位置。
5. 文档解析交付章节、参考、索引与公共文件关系。
6. 检查上下文只读交付事实及所属索引。

### 检查与诊断

1. 来源解析定位项目内部依赖。
2. 依赖判断依次消费层级、业务关系与能力授权。
3. 业务规则验证所属长期职责。
4. 文档结构与归属分别消费同一解析结果。
5. 规则自身检查消费固定注册清单。
6. 诊断按文件、位置和规则编号排序并交付退出码。

### 本地与持续集成

1. lint 必须执行共同基础及 Vue 检查，lint:fix 必须在同一范围执行工具支持的自动修复。
2. lint:full 必须复用共同配置并消费五个运行环境的类型信息完成异步与分支检查。
3. Node 测试必须发现 scripts 下全部共址检查测试。
4. 架构入口必须对真实仓库执行全部正式规则。
5. 展示与标识符入口必须完成所属检查。
6. typecheck 必须依次检查应用、单元测试、Vite 配置、工程脚本与浏览器脚本。

## 规范

- 最终验证与 CI 必须执行 lint:full，日常快速检查必须消费 lint，自动修复必须消费 lint:fix。
- 完整检查必须覆盖异步任务接纳、异步回调使用、等待对象、错误处理范围与封闭分支完整性。
- Node 测试登记必须由所属测试框架管理异步结果；显式后台任务必须保持所属失败接纳边界。
- 混合同步与异步结果的集合、显式默认分支及短路调用必须沿用实际执行语义。
- 模板引号、插值空格与连续空格必须由 Prettier 统一检查。
- CI 的 Rust 全测必须分别在长路径与实际 8.3 短路径的独立进程执行。
- CI 必须实际执行超过 260 字符的路径场景；本地能力不足必须交付未执行清单及验证不完整结果。
- 测试工作区必须排他创建并持有所属文件寿命；失败清理必须保留原始测试错误、实际路径和释放错误。
- Rust 测试必须经统一运行入口交付命令退出码、环境能力、未执行场景、工作区释放及实际报告路径。
- 公共文件与共址测试必须保持公共属性，模块拥有声明严禁覆盖公共文件。
- 前端运行时与类型依赖必须共同参与循环及层级检查。
- 受控入口的运行时导出必须声明公开能力与消费职责。
- 各类源码、文档、导出索引与角色必须在单次执行中建立并复用。
- 同一位置命中的独立规则必须分别交付诊断及所属依据。
- 同名变量的绑定身份必须按词法作用域及实际来源解析。
- 命令与动态模块来源必须使用可静态判定的字面量。
- 实现测试必须继承所属实现的模块或公共属性。
- 实际业务入口必须在独立夹具与真实仓库中共同验收。
- 属性更新事件必须消费 Vue 的 `update:modelValue` 约定，动作事件必须采用 kebab-case。
- 新增约束必须覆盖合法与触发输入，断言必须验证编号、位置、证据与期望职责。
- 本地与 CI 必须使用相同 npm 验证入口。
- 直接由 Node 执行的工程脚本必须采用 NodeNext 解析，Vite 装配必须采用 Bundler 解析。
- 应用、单元测试、Vite 配置、工程脚本与浏览器脚本必须分别消费所属运行环境的类型配置。
- 跨环境消费的 JavaScript 实现必须通过源码 JSDoc 交付类型，严禁使用同名声明文件覆盖实现推导。
- 测试、注释、字符串与生产引用必须按实际语义分别处理。
- 展示静态检查必须排除路径段为 test 的目录内源码；正式展示依赖检查严禁消费测试目录中的定义。
- 生产过滤必须保留原始位置及测试项之后的生产引用。
- 规则必须登记稳定编号、现行依据和实现来源。
- 路径边界检查必须覆盖展开入口归属、磁盘身份比较及原始 Path 经局部赋值进入字符串键的调用，诊断必须交付实际位置、对象及正式入口。
- 计划工作区必须保留在路径清单，并且严禁进入架构与展示源码解析。
- 诊断必须携带规则编号、文件、行、列与原因，关系诊断必须携带实际目标或符号及期望职责。
- 转导出与整模块引用必须保留表面入口及原始定义来源。
- 显式 JavaScript 扩展名的来源解析必须按 TypeScript 扩展名替换顺序识别对应源码与声明。

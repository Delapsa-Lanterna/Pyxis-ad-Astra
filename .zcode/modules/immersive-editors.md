# 沉浸式编辑器

## 定义

沉浸式编辑器以游戏信息面板组织实体的直接字段、基础统计和只读关联，并通过联合编辑会话提交所属记录。

## 边界

| 对象                      | owner                          | 消费职责                                 |
| ------------------------- | ------------------------------ | ---------------------------------------- |
| 原文、输入、dirty、saving | 编辑会话与 FieldInputs         | 展示组件提交或取消所属输入               |
| 可编辑内容与版本          | 联合编辑会话                   | 舰船声明规格、舰船 CSV 与所属描述记录    |
| 来源、授权目标与原子写入  | 后端联合能力                   | 前端消费正式快照、冲突与 receipt         |
| 展示值、公式与字段绑定    | 舰船领域投影                   | 共享组件消费标签、schema、来源与动作     |
| 固定令牌                  | 沉浸式 appearance              | WindowShell 与唯一主题 effect 消费       |
| 窗口实例与关闭            | 正式窗口能力与关闭守卫         | 沉浸式编排消费创建、聚焦、身份交接与释放 |
| 草稿历史                  | 快照历史原语                   | 字段提交登记前后业务值                   |
| 关联读取与媒体等待        | ReadTicket 通道与媒体 registry | ViewModel 登记当前来源与贴图集合         |

## 链路

### 打开

1. 舰船详情动作捕获 session、Mod、CSV rowKey 与物理目标。
2. 沉浸式编排查询完整窗口身份并聚焦已有实例。
3. 新实例先完成 CSV 保存交接，以后端行身份读取权威根。
4. 联合编排协调规格、舰船 CSV 与描述的物理范围并重读快照。
5. 正式窗口能力创建窗口，根组件装配固定配色与设置镜像。
6. ViewModel 以联合基线建立所属草稿、历史、关联投影与贴图集合。

### 字段编辑与保存

1. 用户点击直接值或派生值，字段浮层消费稳定字段身份与来源 schema。
2. 原始输入进入所属 FieldInputs；提交经过字段转换更新独立记录并登记历史。
3. 保存提交活动输入，联合编排协调相关保存并执行三方比较与确认。
4. 后端在根事务中提交实际修改的 CSV、规格及描述。
5. 会话接纳实际基线并映射后续草稿，窗口更新登记、URL 与标题，历史映射到正式身份。
6. 已提交 receipt 进入现有历史、项目投影、缓存失效与广播。

### 来源与释放

1. 来源提示展示 Core、缺失记录、实际路径与共享引用。
2. 用户确认 Core 覆盖，联合事务原样建立当前 Mod 记录并接纳实际快照。
3. 系统引用变化经所属关联通道读取草稿来源；贴图由 registry 替换集合。
4. 外部版本由联合会话接纳或暂存，身份通知经所属通道映射草稿与历史。
5. 关闭守卫等待保存与同步并确认最新 dirty；窗口销毁或 session 释放撤销读取、输入、媒体及目标登记。

## 规范

- 四类沉浸式身份必须包含 sessionId、modRoot、kind 与 id；窗口外观必须固定为游戏暗色并注明统计口径。
- 共享组件只允许消费领域提供的字段、schema、显示值、来源与动作；业务草稿与保存必须归现有会话和联合能力。
- 舰船名称、定位、设计类型、系统与性能必须消费舰船 CSV；尺寸、槽位、内置引用与贴图必须消费实际规格；描述必须消费所属描述记录的 text1–text5。
- 船员编制必须绑定 min crew 与 max crew；部署点数必须消费 supplies/rec；护盾维持必须按 shield upkeep × flux dissipation 计算；相位消耗必须按来源系数 × max flux 计算。
- 派生项必须展示公式和来源，点击必须编辑来源参数；插件效果必须按零效果计算，脚本说明必须展示静态内容与来源提示。
- 系统引用必须通过正式来源选项选择；挂载、内置武装与插件展示只允许读取关联投影。
- Core 字段必须先经显式确认建立 Mod 覆盖；缺失字段必须通过明确字段提交建立，缺失规格必须消费正式构造器。
- 单行字段必须以 Enter 提交、Esc 取消，多行描述必须以 Ctrl+Enter 提交；非法原文必须保留并定位，活动输入必须参与保存和关闭判定。
- 字段身份必须随所属记录身份映射保持稳定；保存期间后续输入与草稿历史必须保留，receipt 重试必须复用实际提交。
- 初始窗口必须为 1160 × 760 px，最小尺寸必须为 860 × 560 px；窄窗口必须按分组排列，内容滚动与固定操作区必须分别拥有布局空间。
- 联合基线、关联投影与媒体必须消费所属读取通道；替换、失效、销毁及会话结束必须释放原等待与集合。

## 陷阱

- 严禁将只读关联记录加入舰船可编辑集合。
- 严禁以规格 hullName 替代舰船 CSV 名称写入。
- 严禁将游戏运行时插件效果作为基础配置统计来源。
- 严禁在展示组件中直接写盘或接纳 receipt。
- 严禁在字段浮层中建立独立 dirty、保存或历史 owner。

# 沉浸式编辑器

## 定义

沉浸式编辑器以游戏信息面板组织实体的直接字段、基础统计和只读关联，并通过联合编辑会话提交所属记录。

## 边界

| 对象                      | owner                          | 消费职责                                 |
| ------------------------- | ------------------------------ | ---------------------------------------- |
| 原文、输入、dirty、saving | 编辑会话与 FieldInputs         | 展示组件提交或取消所属输入               |
| 可编辑内容与版本          | 联合编辑会话                   | 领域声明根规格、所属 CSV 与描述记录      |
| 来源、授权目标与原子写入  | 后端联合能力                   | 前端消费正式快照、冲突与 receipt         |
| 展示值、公式与字段绑定    | 舰船、武器与战机领域投影       | 共享组件消费标签、schema、来源与动作     |
| 固定令牌                  | 沉浸式 appearance              | WindowShell 与唯一主题 effect 消费       |
| 窗口实例与关闭            | 正式窗口能力与关闭守卫         | 沉浸式编排消费创建、聚焦、身份交接与释放 |
| 草稿历史                  | 快照历史原语                   | 字段提交登记前后业务值                   |
| 关联读取与媒体等待        | ReadTicket 通道与媒体 registry | ViewModel 登记当前来源与贴图集合         |

## 链路

### 打开

1. 舰船、武器或战机详情动作捕获 session、Mod、CSV rowKey 与所属表的物理目标。
2. 沉浸式编排查询完整窗口身份并聚焦已有实例。
3. 新实例先完成 CSV 保存交接，以后端行身份读取权威根。
4. 联合编排协调根规格、所属 CSV 与描述的物理范围并重读快照。
5. 正式窗口能力创建窗口，根组件装配固定配色与设置镜像。
6. ViewModel 以联合基线建立所属草稿、历史、关联投影与贴图集合。

### 字段编辑与保存

1. 用户点击直接值或派生值，字段浮层消费稳定字段身份与来源 schema。
2. 原始输入进入所属 FieldInputs；提交经过字段转换更新独立记录并登记历史。
3. 保存提交活动输入，联合编排协调相关保存并执行三方比较与确认。
4. 后端在根事务中提交实际修改的 CSV、规格及描述。
5. 会话接纳实际基线并映射后续草稿，窗口更新登记、URL 与标题，历史映射到正式身份。
6. 已提交 receipt 进入现有历史、项目投影、缓存失效与广播。

### 来源与释放

1. 来源提示展示 Core、缺失记录、实际路径与共享引用。
2. 用户确认 Core 覆盖，联合事务原样建立当前 Mod 记录并接纳实际快照。
3. 系统、弹体、规格分支、贴图或伤害类型变化经所属关联通道读取草稿来源；媒体由 registry 替换集合。
4. 外部版本由联合会话接纳或暂存，身份通知经所属通道映射草稿与历史。
5. 关闭守卫等待保存与同步并确认最新 dirty；窗口销毁或 session 释放撤销读取、输入、媒体及目标登记。

## 规范

- 战机必须按名称、设计类型、描述、技术数据、系统、武装和来源区顺序展示；预览必须位于技术数据左侧80×80px区域，间隔必须为10px。
- 战机名称必须消费有效舰体名称和装配displayName，并在同一浮层提交；联队role desc必须优先于角色枚举，乘员必须消费min crew，其余直接值必须绑定实际来源字段。
- 战机技术数据必须消费原版swarm、支援范围、装甲和防御分支；系统说明必须消费SHIP_SYSTEM静态描述及高亮，武装必须按有效武器槽统计并以逗号连接。
- 战机窗口必须为430×700px、最小340×480px；数值行必须消费武器共用的15px单行与3px行间隔，字形必须保持物理像素对齐。
- 战机字段身份必须消费稳定来源角色与字段路径；联队改名必须按CSV rowKey重读并共同映射窗口、输入、草稿与历史。
- 引用切换必须先等待保存与同步、提交输入并确认保存当前草稿；引用提交必须消费原联合事务，接入新来源必须经权威重读，取消或提交失败必须保留原引用与草稿。
- 来源覆盖必须按所选记录确认实际文件与共享影响；缺失装配、舰体与Skin必须消费正式构造器及必填关联字段，来源读取必须由所属ReadTicket接纳。
- 武器面板必须按名称、设计类型、描述、主数据、辅助数据顺序展示；标签与计算等级必须使用中文，Mod 原文与覆盖文本必须保持原文。
- 武器名称、性能与伤害类型必须消费武器 CSV；武器类型、尺寸、挂载覆盖与发射模式必须消费实际规格，弹体只允许作为只读关联与独立窗口目标。
- 武器描述必须按武器 ID 与 WEAPON 类型定位；主要用途必须优先消费 primaryRoleStr，再消费所属描述 text2。
- 武器派生值必须按原版发射点、发射模式、充能、连射、光束周期与弹药恢复投影；提示覆盖与实际参数必须在同一浮层编辑。
- 显示设置必须通过所属 CSV 的隐藏标记、自定义文本与高亮字段提交；高亮必须使用逐字文本片段，严禁解释为 HTML。
- 武器静态图标必须消费正式炮塔层顺序与原点，并完整显示编号 PNG 首帧；伤害类型图标必须由后端配置解析返回 ResourceRef。
- 多字段浮层必须在全部输入有效后一次交付字段集合并登记一次历史；失败与取消必须保留所属原文或取消整个待提交集合。
- Core pulse 覆盖必须先选择 projectile 或 beam，补齐所属必读字段并确认授权目标，再由联合事务创建当前 Mod 内容。
- 四类沉浸式身份必须包含 sessionId、modRoot、kind 与 id；窗口外观必须固定为游戏暗色并注明统计口径。
- 共享组件只允许消费领域提供的字段、schema、显示值、来源与动作；业务草稿与保存必须归现有会话和联合能力。
- 舰船名称、定位、设计类型、系统与性能必须消费舰船 CSV；尺寸、槽位、内置引用与贴图必须消费实际规格；描述必须消费所属描述记录的 text1–text5。
- 船员编制必须绑定 min crew 与 max crew；部署点数必须消费 supplies/rec；护盾维持必须按 shield upkeep × flux dissipation 计算；相位消耗必须按来源系数 × max flux 计算。
- 派生项必须展示公式和来源，点击必须编辑来源参数；插件效果必须按零效果计算，系统说明必须消费所属描述记录。
- 系统引用必须通过正式来源选项选择；挂载、内置武装与插件展示只允许读取关联投影。
- Core 字段必须先经显式确认建立 Mod 覆盖；缺失字段必须通过明确字段提交建立，缺失规格必须消费正式构造器。
- 单行字段必须以 Enter 提交、Esc 取消，多行描述必须以 Ctrl+Enter 提交；非法原文必须保留并定位，活动输入必须参与保存和关闭判定。
- 字段身份必须随所属记录身份映射保持稳定；保存期间后续输入与草稿历史必须保留，receipt 重试必须复用实际提交。
- 武器与战机默认内容必须为400px，初始窗口必须为430×700px，最小必须为340×480px；舰船默认内容必须为800px，初始窗口必须为830×700px，最小必须为430×480px。
- 展示必须消费内置正文、分组标题与舰船标题位图字库；字形、字距、基线、kerning与图集必须共用每WebView的正式装配，缺字必须显示方框与Unicode诊断并保留原文。
- 武器单行必须采用原版15px单元格并居中17px中文字形；舰船单行必须消费17px字体行高，数据行间隔必须为3px；标题条必须采用分组字体行高加3px；舰船列间隔必须为9px，武器图标与数据间隔必须为10px。
- 窗口尺寸变化必须保持字形尺寸，canvas必须按DPI调整像素尺寸；字形绘制与画布呈现必须对齐物理像素，滚动必须更新画布原点；舰船内容低于690px必须纵向排列分组，低于430px必须纵向排列后勤列，重排必须保留DOM、浮层与输入。
- 标题行动作必须与标题条垂直居中，文字必须消费分组标题字库。
- 武器图标必须采用80×80px区域，并按原版挂载类型、尺寸、线宽、层次与颜色绘制槽位；贴图必须按原版方向、层次、原点与已装载导弹引用绘制。
- 舰船预览必须使用200×200px区域与原版相对缩放规则；标签、数值、设计类型、倍率、船员与燃料必须分别消费正式颜色角色。
- 联合基线、关联投影与媒体必须消费所属读取通道；替换、失效、销毁及会话结束必须释放原等待与集合。

## 陷阱

- 严禁将只读关联记录加入根实体可编辑集合。
- 严禁以规格 hullName 替代舰船 CSV 名称写入。
- 严禁将游戏运行时插件效果作为基础配置统计来源。
- 严禁在展示组件中直接写盘或接纳 receipt。
- 严禁在字段浮层中建立独立 dirty、保存或历史 owner。

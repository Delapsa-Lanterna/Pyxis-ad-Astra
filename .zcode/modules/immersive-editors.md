# 沉浸式编辑器

## 定义

沉浸式编辑器模块提供游戏信息面板形式的多来源字段与装配编辑。

## 边界

- ViewModel 装配联合会话、身份跟随、关联读取与媒体集合，候选 composable 拥有目录和详情读取。
- appearance 提供固定主题令牌，WindowShell 和唯一主题 effect 接纳外观。
- 共享组件拥有外壳、字体角色入口、数值行、字段浮层与控件展示，消费领域提供的字段、来源与动作。
- 内容渲染器拥有舰船、武器与联队的唯一内容布局，窗口壳和装配信息容器分别消费编辑与只读模式。
- 原生实例与关闭归窗口能力和守卫，沉浸式编排消费创建、聚焦、身份交接与释放。
- 字体模块拥有外部定义、图集、排布、逐字体回退和测量，沉浸式领域拥有角色映射与所属强调色，窗口以所属 session 提供字体运行态。
- 武器组组件拥有独立临时调整，确认或保存交付一次会话动作。
- 编辑会话与 `FieldInputs` 拥有原文、dirty、saving 与输入提交，快照历史拥有前后业务值。
- 联合会话拥有可编辑记录集合、基线和版本，后端联合能力提供来源图、授权目标与原子写入。
- 装配场景、武器面板和候选卡消费武器领域的静态装备投影，武器集合的排序与贴图阶段由共享绘制入口交付。
- 装配场景消费共享画布视口、导航与命中，装备动作和模块草稿归联合 ViewModel。
- 领域拥有舰船、武器、战机与装配的信息投影、基础公式和独立草稿转换。

## 链路

### 打开

1. 舰船、武器或战机详情动作捕获 session、Mod、CSV `rowKey` 与所属表的物理目标。
2. 沉浸式编排查询完整窗口身份并聚焦已有实例。
3. 新实例先完成 CSV 保存交接，以后端行身份读取权威根。
4. 联合编排协调根规格、所属 CSV 与描述的物理范围并重读快照。
5. 正式窗口能力创建窗口，根组件装配固定配色与设置镜像。
6. ViewModel 以联合基线建立所属草稿、历史、关联投影与贴图集合。

### 字段编辑与保存

1. 用户点击直接值或派生值，字段浮层消费稳定字段身份与来源 schema。
2. 原始输入进入所属 `FieldInputs`；提交经过字段转换更新独立记录并登记历史。
3. 保存提交活动输入，联合编排协调相关保存并执行三方比较与确认。
4. 后端在根事务中提交实际修改的 CSV、规格及描述。
5. 会话接纳实际基线并映射后续草稿，窗口更新登记、可重载上下文与标题，历史映射到正式身份。
6. 已提交 receipt 进入现有历史、项目投影、缓存失效与广播。

### 装配选择与模块导航

1. 族模板动作捕获装配加载身份，经相关保存交接创建或聚焦窗口。
2. 联合查询返回根装配、独立模块、有效舰体、槽位与来源版本。
3. 网格消费共享画布视口、命中和导航，槽位动作提交活动输入并打开所属选择器。
4. 候选目录按需读取，武器／联队详情按悬停或焦点读取，可见图片进入所属媒体集合。
5. 装备、卸下、归组或类别转换经 ViewModel 提交一次联合草稿动作与历史。
6. 模块导航提交活动输入，切换展示目标并保留全体装配草稿。
7. 联合保存提交实际修改集合，写后接纳目标、版本、身份、历史与 receipt。

### 来源与释放

1. 来源提示展示 Core、缺失记录、实际路径与共享引用。
2. 用户确认 Core 覆盖，联合事务原样建立当前 Mod 记录并接纳实际快照。
3. 系统、弹体、规格分支、贴图或伤害类型变化经所属关联通道读取草稿来源；媒体由 registry 替换集合。
4. 外部版本由联合会话接纳或暂存，身份通知经所属通道映射草稿与历史。
5. 关闭守卫等待保存与同步并确认最新 dirty；窗口销毁或 session 释放撤销读取、输入、媒体及目标登记。

### 装配场景绘制

1. 有效舰体及所属装备进入共享武器排序，每个舰体独立计算顺序。
2. ShipDisplayPanel 的装配阶段依次绘制舰体、全体 UnderSprite、装饰武器主体、子模块及普通武器主体。
3. 原槽位集合交付命中与选区，场景叠加交互标记。

### 只读信息展示

1. 问号入口消费当前主舰或模块的关联快照与装配草稿，候选入口消费所属详情读取通道。
2. 领域投影交付内容与来源，媒体集合交付当前授权图片。
3. 固定内容容器挂载与编辑窗口共用的内容渲染器。
4. 入口与面板交接悬浮及焦点，关闭恢复所属入口。
5. 目标替换、隐藏或卸载释放所属等待和媒体集合。

## 规范

- Core 修改必须通过明确来源选择与覆盖确认，缺失记录必须消费正式构造器和授权目标；缺失字段必须由显式字段提交建立。
- `FieldInputs` 必须登记手填引用与临时调整；保存必须等待异步 finalizer 并消费接纳结果，取消或错误必须阻断当前保存并保留所属原文。
- `JointEditRoot` 必须完整表达 `sessionId`、`modRoot`、kind 与 id；联队行身份必须由 CSV `rowKey` 解析，身份接纳必须共同映射窗口、草稿、输入和历史。
- `ReadTicket` 必须分别管理联合基线、关联、目录、候选详情与动作确认；引用替换、失效、目标变化、销毁和 session 关闭必须释放所属等待与接纳权。
- 位图展示必须保留 DOM 可访问名称；DPI 和窗口重排必须保持逻辑字号、物理像素对齐、浮层目标与活动输入。
- 候选卡必须直接消费目录摘要，完整详情必须由悬停或焦点按独立通道读取；当前装备与详情必须绑定实际非空 ID，Ctrl 比较必须使用独立只读投影。
- 候选图像必须由列表管理可见与邻近集合；窗口图片运行态必须保留已接纳解码和成品，重新可见必须同步消费当前来源的就绪结果，隐藏必须释放所属活跃引用与等待。
- 候选目录必须按 Mod 优先、Core 补集读取，搜索和筛选必须消费排序后的完整目录；三类候选必须默认按 OP 降序，同成本必须保持相对顺序，缺失成本必须保留诊断并置于末尾。
- 共享字段组件只允许提交所属来源记录；多字段浮层必须在全部原文有效后一次交付字段集合，并登记一条联合历史。
- 内容渲染器必须显式消费只读或编辑模式；编辑模式必须由所属会话提供字段能力，只读模式只允许消费投影、来源与媒体结果。
- 只读信息必须消费所属领域内容投影，草稿、原始输入、历史、保存及目标登记必须归所属编辑会话。
- 字体选择必须经领域角色映射交付实际身份，文字与截断测量必须消费字体模块的同一排布能力。
- 字段身份必须使用稳定来源角色与路径；单行输入必须以 Enter 提交、Esc 取消，多行描述必须以 Ctrl+Enter 提交，未完成输入必须参与 dirty、保存和关闭交接。
- 对话层必须拥有所属点击和焦点边界，字段与类别浮层必须挂载在所属 dialog；返回必须交接活动字段、取消手填输入并恢复发起入口焦点。
- 引用切换必须提交输入、等待保存与同步并确认当前相关草稿；提交后必须权威重读来源、版本与资源，取消或提交失败必须保留原引用和草稿。
- 强制安装与手填 ID 必须共用 ViewModel 动作；确认接纳必须核对捕获目标、草稿、输入及候选版本，取消必须保留当前装备和选择器，成功必须登记一次历史。
- 插件两组筛选必须按目录去重计数，组内取并集、组间取交集；普通点击必须单选当前项，Ctrl／Shift 必须切换多选，取消最后一项必须恢复全选。
- 插件目录必须消费 `hidden`、`hiddenEverywhere`、设计类型与 `uiTags`，缺失设计类型必须采用 Common；成本必须消费当前舰级，安装状态必须来自实际装配集合。
- 插件静态详情必须消费 `desc`、`short`、`sModDesc`，脚本参数必须使用明确占位；安装与类别转换必须更新所属草稿并保持选择器。
- 普通、永久与 S 插件动作必须共同调整 `hullMods`、`permaMods` 和 `sMods` 的包含关系；`sModdedBuiltIns` 只允许展示已有强化状态。
- 武器候选必须过滤 CSV `hints` 与规格 `aiHints` 中的完整 `SYSTEM` 标记；筛选必须优先消费 `mountTypeOverride`，类型排和尺寸排各取并集、两排取交集，空选择必须产生空列表。
- 武器归组必须消费全部已装与有效内置武器，每个槽位必须属于一个组；Shift 批量必须按相同武器 ID 与挂载匹配，模式和持续幅能必须消费所属组投影。
- 武器描述必须以武器 ID 与 `WEAPON` 类型定位，用途必须优先消费 `primaryRoleStr`，再消费描述 `text2`；派生值和覆盖文本必须共同绑定实际来源参数。
- 武器来源必须以 CSV 提供名称、性能及伤害类型，以规格提供类型、尺寸、挂载和发射参数；弹体只允许作为只读关联和独立编辑目标。
- 武器筛选初值必须消费当前槽位的原版类型和尺寸规则；安装校验必须核对有效类型、尺寸、指定挂载限制和 `SYSTEM`，强制安装必须显式呈现槽位、候选、来源与原因。
- 武器组必须建立独立七组临时值与比较基线，保留空组及未知组字段；相等提交必须保持会话相等，调整确认或保存必须登记一次联合历史，取消必须恢复打开前分组。
- 武器统计必须消费原版发射点、模式、充能、连射、光束周期与弹药恢复规则；高亮只允许作为逐字片段展示，严禁解释为 HTML。
- 沉浸式基础统计必须明确插件零效果口径；派生项必须提供公式和来源，编辑动作必须提交实际来源参数。
- 清空必须保留内置装备、内置 S 强化、名称、舰体及模块引用与未知字段；确认期间目标、模块集合、草稿或原文变化必须结束请求并保留最新内容。
- 清空必须捕获当前装配及递归模块并按实际记录键去重，确认必须展示实际文件与共享影响；可编辑装备、插件与幅能分配必须形成一条联合历史。
- 界面刷新必须由所属根登记实际来源与动作，并沿现有保存等待、草稿和外部更新接纳流程执行。
- 稳定详情身份必须保持渲染实例；候选读取必须消费现有缓存与 single-flight，隐藏和身份替换必须释放所属票据与媒体等待。
- 系统引用必须消费正式来源选项，说明必须读取所属 `SHIP_SYSTEM` 静态描述；关联武装和插件必须消费有效来源投影。
- 联队名称必须消费有效舰体名称与装配 `displayName`，并在一次字段动作中提交；用途必须优先消费 `role desc`，直接参数必须绑定联队 CSV 或有效舰体的实际字段来源。
- 联队投影必须消费原版角色、swarm 与防御分支；武装汇总必须按有效槽位统计，甲板、候选和内容渲染器的编队必须共同消费 `num`、`formation`、有效舰体及装备的同一场景投影与绘制。
- 舰船名称、定位、设计类型、系统与性能必须消费所属 CSV，几何、槽位、内置引用与贴图必须消费有效规格，描述必须消费所属 `SHIP` 记录的 `text1`–`text5`。
- 舰船船员必须绑定 `min crew` 与 `max crew`，部署点数必须消费 `supplies/rec`；护盾维持必须按 `shield upkeep` × `flux dissipation` 计算，相位消耗必须按来源系数 × `max flux` 计算。
- 装配关联展示必须以同一读取的来源图和引用草稿接纳；等待期间必须保持当前已接纳展示，迟到结果必须消费所属读取票据，编辑草稿与保存必须归原会话。
- 装配可编辑集合必须由根和模块引用图确定；同一模块必须共享实际记录键、草稿与版本，模块导航必须提交活动输入并保留全部所属草稿。
- 装配基础舰体统计只允许查看来源；预算必须计入可编辑武器、非内置联队、普通插件及幅能分配，内置装备和永久插件必须按零 OP 计费。
- 装配字段身份必须表达根与模块槽位角色，改名必须共同映射记录键、输入、历史与导航；保存期间新增输入和草稿必须按实际基线保留。
- 装配容量与耗散必须消费有效舰体基础值及配置 `fluxPerCapacitor`、`dissipationPerVent`；超预算、超舰级上限、不兼容和缺失引用必须提供定位诊断并允许保存。
- 装配武器替换必须保留所属组，新增必须进入首组；联队卸下必须保留甲板索引，内置装备必须保持所属来源权限。
- 装配舰船信息必须消费当前主舰或模块的有效舰体及逐舰体展示绑定，容量、耗散、预算和完整装备必须消费当前装配草稿投影；引用维护和正式新建必须消费主窗口入口。
- 资源必须消费后端授权 `ResourceRef` 和所属媒体集合；场景、图标与槽位命中必须共用正式坐标、层序和有效 Skin 来源，解码接纳必须服从当前生命周期。

## 陷阱

- 以 `hullName` 写回舰船 CSV 名称会混淆规格名和展示名的来源。
- 在字段浮层建立独立 dirty 和历史会让保存与关闭判定分叉。
- 在展示组件直接写盘或接纳 receipt 会绕过联合会话与提交同步。
- 把只读关联记录纳入可编辑集合会扩大实际写入范围。
- 把游戏运行时插件效果计入基础统计会改变配置数据的计算口径。

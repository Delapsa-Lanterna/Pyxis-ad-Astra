# 后端文件读写与变更集

## 定义

后端文件读写与变更集模块提供授权磁盘操作及可回放的文件和目录变更。

## 参考

### 拥有

- `src-tauri/src/io/csv_files.rs`：CSV 文件读写与路径上下文。
- `src-tauri/src/io/faction_index.rs`：索引引用的实际根与父链授权。
- `src-tauri/src/io/faction_index_test.rs`：势力索引路径授权和读入行为验证。
- `src-tauri/src/io/file_changes.rs`：changeset 构建、应用与回放。
- `src-tauri/src/io/file_versions.rs`：规范路径版本采集与指纹核对。
- `src-tauri/src/io/json_files.rs`：JSON 文件读取及匹配版本交付。
- `src-tauri/src/io/mod.rs`：底层文件、路径及 changeset 能力导出。
- `src-tauri/src/io/paths.rs`：磁盘路径展开、父链授权与改名目标解析。
- `src-tauri/src/io/text.rs`：UTF-8 文本读取，拥有 BOM 剥离与 CP1252 归一化入口。

### 消费

- `src-tauri/src/models/file_changes.rs`：文件变更、目录内容快照及统一回放方向。
- `src/shared/types/file-changes.types.ts`：文件变更、目录快照与回放方向的基础契约。

### 关联

- `src-tauri/src/services/write_transactions.rs`：根写入租约、版本复核、历史登记、回放及投影提交。
- `src/shared/lib/paths.ts`：文件系统、资源及游戏目录的路径纯规则。

## 边界

- `FileChangeRecord` 表达路径、存在状态与内容快照，目录事件展开实际文件影响。
- FsRootBoundary 提供 canonical 根、实际目标与已有父链授权，全部磁盘入口共用该边界。
- IO 拥有磁盘路径、遍历、读取、写入、删除和 changeset 应用。
- parser 和 renderer 拥有格式语义，IO 按调用方文本写入 UTF-8 字节。
- 回放消费既有快照并核对当前磁盘授权，错误保留目标与上下文。
- 根事务提供版本、FIFO 租约与失败恢复，IO 返回实际应用结果。

## 链路

### 文本读取

1. 保存链路或编辑器请求读取目标文件。
2. IO 读取字节并共同生成文件版本，解码入口剥离 UTF-8 BOM。
3. 已知 CP1252 智能引号按统一映射归一化。
4. 返回文本与路径上下文。

### 保存与 changeset 构建

1. 保存入口提交目标路径与文本。
2. IO 校验 canonical root、父链链接与路径边界。
3. 写入前快照当前内容，写入 UTF-8 无 BOM 字节。
4. 构造 before/after `FileChangeRecord` 并展开目录事件。
5. 返回 changeset 与失效路径给 ProjectSession。

### 回放

1. 文件历史回放以确认后的 changeset 请求回放。
2. IO 重校验全部路径归属与父链。
3. 按 before/after 快照逆向或正向应用变更。
4. 根保存租约必须在写入失败后恢复本次修改，恢复受阻必须等待所属请求处理。

## 规范

- `FileChangeRecord` 必须共同承载 `beforePath`、`afterPath` 与前后内容；普通写入必须使用相同路径，文件或目录改名必须使用源与目标路径。
- 根写入租约必须统一转换回放方向；撤销必须反转路径、内容与执行顺序，文件及目录原语必须消费转换后的目标内容。
- Windows 仅大小写改名必须按同一物理文件检查占用，并且必须由正式文件改名原语交接实际名称。
- `write_utf8_no_bom` 必须按调用方提供的文本原样写入 UTF-8 字节；换行、缩进与序列化规则归各格式 renderer。
- 写入必须携带读取版本凭据并在出队执行时比较；冲突必须返回 `write.version_conflict` 和目标路径，严禁写入或推进历史。
- 势力索引目标、规格目录与指纹输入必须经 FsRootBoundary 授权之后读取或遍历。
- 变更快照必须记录目标实际存在状态与内容，撤销必须消费实际 before 快照。
- 同一 canonical 根的写入必须按 FIFO 执行，嵌套同步写服务必须共享事务租约；不同根必须独立执行，锁序必须为根租约、session 状态、缓存。
- 文本读取必须消费统一 CP1252 归一化映射，保存必须写回归一结果；映射必须保持独立字节与合法 UTF-8 标量的边界。
- 新建 Mod 的 `mod_info.json` renderer 必须输出 UTF-8 无 BOM 与 CRLF；其它格式遵守各自 parser 或保存模型的输出语义。
- 构造、应用、失败恢复、版本校验与回放必须共同消费双路径；撤销必须同时反转路径、存在状态与内容快照。
- 根保存租约必须持有实际写入前内容和存在状态，写入失败必须逆序恢复已执行及部分执行步骤，恢复重试必须继续未恢复位置。
- 文本与二进制恢复必须保留原始字节，文件已恢复到原内容时必须释放该恢复位置。
- 写入与恢复必须重新核对所属根和实际父链，根缺失必须等待恢复原位置。
- 每个保存入口只允许写所属模块声明的持久化目标；关联文件操作必须由同一正式保存模型显式声明。
- 源内容与文件版本必须从同一次读取字节生成，文本解码必须继续消费正式编码入口。
- 源记录与目标凭据必须在同一 FIFO 租约中复核；缺少所属目标的读取凭据必须以 write.version_scope_missing 拒绝写入。
- 目录必须以正式目录事件表达，严禁让前端递归枚举。
- 目录版本必须汇总排序后的子文件相对路径与内容版本，磁盘核对及 changeset 接纳必须消费同一算法。
- 联合业务保存必须在同一根租约中装配全部 changeset，版本与失败恢复必须消费实际目标集合；身份渲染必须在应用前完成。
- 路径展开与身份规范化必须归 IO；现存目标必须交付规范长路径，缺失目标必须展开现存父目录并保留剩余段，改名目标必须保留要求的末级名称；消费者只允许接纳 IO 输出。
- 路径授权必须核对目标及已有父链的链接边界，历史回放必须重新完成授权。

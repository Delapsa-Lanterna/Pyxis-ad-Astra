# 来源变化监听

## 定义

来源变化监听模块管理实际来源根的磁盘监听与变化批次寿命。

## 参考

### 拥有

- `src-tauri/src/services/source_watch.rs`：根订阅、原生监听、变化合批与释放。

### 消费

- `src-tauri/src/errors.rs`：监听错误与结构化诊断。
- `src-tauri/src/io/paths.rs`：实际来源根授权。
- `src-tauri/src/models/project_identity.rs`：Windows 根身份比较。

### 装配

- `src-tauri/src/services/mod.rs`：监听能力登记。
- `src-tauri/src/services/project_sync/source_changes.rs`：订阅寿命、批次入队和执行装配。

## 边界

- 原生监听实例按 canonical 物理根共享。
- 订阅持有所属来源根的监听寿命。
- 全局监听默认关闭并保留目录订阅；开启时按物理根恢复监听并合并一次重扫，关闭时释放原生监听及待交付事件，回调按监听代次接纳。
- 原生回调收集路径、成对改名及监听诊断。
- Windows 分开发送的旧名和新名在同一批次按相邻事件与 tracker 配对。
- 根工作线程交付已合并变化，根队列的执行等待由项目同步持有。
- 解析、正式内容与草稿接纳分别由所属消费者维护。

## 链路

### 订阅与交付

1. 消费方在读取基线前订阅实际来源根。
2. 同根订阅共享原生监听并在基线登记后激活。
3. 原生事件按安静窗口及最长等待共同形成批次。
4. 根工作线程交付当前批次并继续接纳后续事件。
5. 最后订阅释放原生监听并等待所属工作线程结束。

## 规范

- 首次读取期间的事件必须保留至消费方激活。
- 合批使用 40ms 安静窗口与 500ms 最长等待，最长等待约束批次入队。
- 每根必须只持有一个执行中批次及一个合并中的后续批次。
- 读取访问事件必须在原生回调内排除，改名保留实际对应关系。
- 未配对旧名必须在批次交付、监听重启及配置切换时释放，其它文件事件必须结束较早旧名的配对等待。
- 监听失败必须交付实际根及原始诊断，明确重试重新建立监听并请求重扫。
- 释放必须结束所属原生回调与工作线程，已释放订阅的事件严禁进入新订阅。

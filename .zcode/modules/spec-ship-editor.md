# Spec 舰船编辑器

## 定义

舰船编辑器模块在独立窗口提供舰船规格的画布与字段编辑。

## 参考

### 拥有

- `src/app/components/spec-editor/ship/`：舰船画布、检查器与行为测试。
- `src/app/composables/spec-editor/ship/`：舰船字段、动作、视口及内置武器依赖生命周期。
- `src/app/renderers/spec-editor/ship/`：舰船静态场景、图层与几何绘制。
- `src/domain/spec-editor/ship/`：舰船文档、几何、点位及内置武器投影规则。
- `src/services/spec-ship-editor.service.ts`：舰船规格、草稿贴图及内置武器来源的查询入口。

### 消费

- `src/app/composables/canvas/use-canvas-editor.ts`：舰船消费的共享画布交互、选区和动作提交入口。
- `src/app/composables/editors/use-resource-reference.ts`：贴图引用选择。
- `src/app/composables/spec-editor/use-spec-editor-window-view-model.ts`：四类规格目标会话、保存、身份与外部基线接纳。
- `src/domain/editors/lib/geometry.ts`：舰船与武器坐标、角度、距离及边界线段纯规则。
- `src/domain/editors/lib/mirror.ts`：舰船消费的共享几何镜像规则。
- `src/shared/ui/FieldHints.vue`：检查器说明的共同展示。

### 关联

- `scripts/architecture/rules/editor-module-boundary.mjs`：编辑器组件边界规则。
- `src-tauri/src/services/project/write/entity_description.rs`：舰船与武器描述行的身份改名和同根暂存。

## 边界

- SpecShipEditor 绑定控件、画布事件与编辑 ViewModel 动作。
- builtInWeapons 提供内置装备集合，槽位提供几何与挂载；内置展示 ViewModel 持有所属来源、媒体、解码与逐项诊断。
- 场景拥有舰船视觉规则与图层顺序，资源运行态提供可用贴图及着色结果。
- 场景消费战斗舰船的装备排序与绘制阶段，内置展示覆盖所属全部编辑模式。
- 外部快照由会话直接接纳或暂存，保存期间的新动作保持所属历史。
- 画布骨架交接指针阶段，共享选区管理目标身份，编辑文档拥有工作值、动作边界与历史。
- 窗口会话拥有目标、版本、dirty 和保存，所属图像依赖拥有资源读取。
- 编辑 ViewModel 装配 `.ship` 文档、模式、领域动作与场景输入；CSV 与描述身份由正式身份事务更新。
- 缺失规格的导入建立待保存草稿，实际文件状态由成功写入结果确定。
- 规格窗口按实体身份登记，沉浸式窗口通过联合交接协调共同物理范围。
- 贴图浏览消费后端安全相对路径，引用字段归规格草稿。

## 链路

### 打开与画布就绪

1. 窗口按 `.ship` 目标打开并加载 bundle。
2. 组件接入编辑 ViewModel，编辑文档接纳归一化工作值。
3. 骨架挂载窗口事件、resize 与快捷键分发。
4. 贴图运行态加载当前资源，编辑 ViewModel 接纳尺寸并自适应缩放。
5. 领域投影提供绘制几何，编辑 ViewModel 交接选区、视口、资源与配色，舰船场景绘制画布。

### 画布编辑

1. 用户在总览、范围、边界、武器、甲板或引擎模式间切换。
2. 左键按模式拖动中心、护盾、半径、槽位、引擎或边界点。
3. Shift/Ctrl/Alt 组合执行新增、复制、半径或角度调整。
4. 空格开关镜像模式，配对元素成对生效。
5. 释放指针在动作边界提交一次 draft。

### 内置武器展示

1. 当前草稿的 builtInWeapons 进入只读来源查询，武器 ID 去重进入候选缓存，舰船 CSV 提供 hints。
2. 槽位 ID 关联当前草稿几何，规格、弹体和授权资源交付共享展示投影。
3. 媒体集合接纳资源，图像运行态按加载身份解码。
4. 舰体、全体 UnderSprite、排序后的武器主体及编辑标记依次绘制。
5. 资源诊断按槽位 ID、武器 ID 或贴图路径交付检查器。
6. 引用、外部接纳或关联失效更新来源，窗口和 session 释放所属读取及媒体。

### 检查器编辑

1. 检查器事件进入编辑 ViewModel 的字段动作。
2. 字段动作提交 draft，并通过舰船场景重绘画布。
3. T 键、列表锁定与具体港口选择经共用画布入口展开目标分组并定位实际字段编辑区。

### 保存

1. 保存经窗口 ViewModel 进入编辑器写链路。
2. 实际写盘快照接纳为 base，完整 receipt 进入统一历史、会话投影与提交通知链路。
3. dirty 时外部版本暂存并提示。

## 规范

- builtInWeapons 必须以对象形状的 JSON 输入提交，原始输入必须登记到所属目标会话并参与保存、关闭与外部版本保护。
- 原规格未声明 `descriptionId` 时，`hullId` 改名必须在同一 changeset 中将旧 ID 的 `SHIP` 描述记录改为新 ID；显式 `descriptionId` 必须保持所属引用语义。
- 同 ID 保存必须使用实际已加载路径；修改 `hullId` 必须保留原目录并同步所属 CSV 的 ID 字段与文件历史。
- 引擎必须消费共享普通满推力静态成品及正式样式资源；正式、镜像与操作预览必须共同生成展示列表，层序必须消费有效 RENDER_ENGINES_BELOW_HULL hint，控制点必须在编辑覆盖层。
- 用户主动加载成功必须同步实际贴图宽高；真实无图首次加载必须通过中心字段赋值居中，附属几何必须保留相对坐标。
- 画布与检查器必须通过编辑文档的动作入口更新所属草稿，dirty 外部内容必须暂存，保存必须提交当前指针位置并结束动作。
- 界面刷新必须由所属根登记实际来源与动作，并沿现有保存等待、草稿和外部更新接纳流程执行。
- 目标定位必须将武器槽与甲板映射至标识符、引擎映射至角度、中心与护盾映射至首个坐标字段、港口与边界点映射至所属坐标输入行。
- 组内增删必须捕获所属选中对象；甲板港口动作必须绑定甲板身份，引擎样式选项必须消费正式资源目录。
- 编辑器内部显示和编辑 `.ship` 的 `hullName`；编辑器外的舰船显示名称必须优先使用 `ship_data.csv` 的 `name`，仅在该名称缺失时才允许 `hullName`。
- 舰体引用、资源引用必须以后端 `ResourceRef` 或后端校验的相对路径表达。
- 舰船新建与关联创建必须消费共享模板构造；ID 与 `hullName` 必须由明确创建参数装配，builtInWeapons 必须保留全部原始槽位键。
- 贴图浏览只允许选择 Mod 根内 PNG，并把授权相对路径原样提交为 `spriteName`；路径与加载后的几何更新必须分别消费普通编辑动作。
- 锁定港口必须保留甲板下标与港口下标；输入校验失败必须保留原输入、所属目标与锁定身份。
- 镜像新增、调整与删除必须成对生效，中轴元素必须作为单件处理；镜像联动只允许作用于正式几何集合。
- 镜像模式按空格开关，覆盖武器槽（含甲板）、引擎与碰撞边界；配对只按几何条件实时计算，严禁按下标或 ID 记忆。
- 默认描述改名必须保留描述文本、未知列、行序与注释身份；目标 `SHIP` 描述 ID 占用必须拒绝整次提交，描述文件版本必须归所属保存凭据与协调范围。

## 陷阱

- dirty 时应用外部版本会覆盖未保存画布编辑。
- 在编辑器内重建命中或选区会让画布语义偏离统一骨架。
- 直接修改 ship CSV 行会让 CSV 权威与规格文件分叉。
- 贴图浏览复制文件进 Mod 会破坏纯引用边界。
- 镜像配对按下标记忆会让删除后错配对侧元素。

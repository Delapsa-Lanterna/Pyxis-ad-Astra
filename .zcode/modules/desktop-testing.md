# 桌面测试

## 定义

桌面测试模块通过独立原生应用执行功能验收与显示性能测量。

## 参考

### 拥有

- `scripts/desktop/`：独立构建、统一运行入口、应用寿命、样本、场景及报告。
- `src-tauri/tauri.desktop-testing.conf.json`：测试应用标识、原生窗口和调试参数。
- `src/test/desktop/`：注入真实 WebView 的页面探针。
- `tsconfig.desktop-scripts.json`：桌面驱动的 Node 与 DOM 严格类型环境。

### 消费

- `scripts/shared/sample-statistics.mjs`：正式测量的统一统计。
- `scripts/shared/test-workspace.mjs`：排他工作区、报告预留及目录释放。
- `src-tauri/tauri.conf.json`：正式应用的基础构建与装配配置。
- `src/app/`：真实桌面窗口、组件与输入。
- `src/domain/`：页面探针读取的正式展示模型。
- `src/shared/types/`：正式运行协议及业务模型。
- `tsconfig.base.json`：共同严格类型约束。

### 装配

- `eslint.config.js`：桌面脚本的完整类型检查装配。
- `package.json`：桌面构建、场景执行、资源测试及类型检查入口。

### 关联

- `CONTRIBUTING.md`：桌面测试的正式命令与参数说明。

## 边界

- 桌面运行持有本次启动的独立 Windows 桌面、原生进程及调试连接。
- 功能与性能场景消费同一启动、就绪和正常关闭流程。
- 样本工作区持有生成或复制的游戏与 Mod 文件。
- 页面探针消费真实组件与数据模型。
- 报告持有每次运行的结果、诊断、日志与截图。
- 统计工具与排他目录工具保持公共属性。

## 链路

### 构建与执行

1. 构建入口读取桌面测试配置并交付独立 Cargo 产物。
2. 执行入口预留报告并建立样本工作区。
3. 运行基础核对调试端口并排他创建工具及 WebView 目录。
4. 原生宿主创建独立 Windows 桌面并在其中启动应用，驱动连接真实窗口并等待应用就绪。
5. 来源同步或 CSV 性能场景执行检查、采样及截图。
6. 所属应用经正常关闭交付日志并释放连接与工具目录。
7. 样本工作区释放，报告交付 JSON、Markdown 与实际退出码。

## 规范

- 桌面测试必须使用独立应用标识、构建目录、工具目录、WebView 资料目录及 Windows 桌面。
- 应用及全部子窗口必须在所属独立桌面内运行；宿主严禁切换用户输入桌面，应用消费正式窗口显示与聚焦流程。
- 宿主必须使用 Windows 普通用户权限令牌启动测试进程，所属桌面授权覆盖当前用户及 WebView2 沙箱。
- 原生宿主必须在应用退出后释放进程及桌面句柄；原生隔离验收分别核对线程内输入焦点与系统输入桌面的前台焦点。
- 原生启动失败必须交付进程原始输出及退出码，严禁切换用户输入桌面或自动改在用户桌面执行。
- 样本必须在排他工作区内生成或复制，文件动作只允许作用于本次样本。
- 显式报告输出必须排他预留，已有文件及目录完整保留。
- CSV 性能必须默认测量 30 次，视口为 1360×860、DPR 1.5，可视字段 P95 以 200ms 为上限。
- 页面探针必须在字段及可视资源就绪后消费随后绘制帧，原始样本与统计共同交付。
- `--dry-run` 必须交付实际执行配置，严禁创建目录、启动应用或写入报告。

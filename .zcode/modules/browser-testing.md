# 浏览器预览与测试

## 定义

浏览器预览与测试模块提供隔离的浏览器预览、功能验收、testbed 性能评估及测量报告。

## 参考

### 拥有

- `scripts/browser/`：浏览器服务、预览构建、自动验收、桌面 CSV 测量、性能对照及报告工具。
- `src/test/browser/`：场景登记、只读游戏数据、样本与窗口替身、聚合校对页、操作、测量及对应测试。

### 消费

- `scripts/shared/`：仓库扫描、样本统计及排他测试工作区。
- `src/app/`：正式窗口根、业务组件、主题与反馈装配。
- `src/domain/`：正式领域转换、字段定义、编辑与展示规则。
- `src/shared/`：业务协议、错误、输入与资源公共能力。
- `src/test/fixtures/`：共享领域、资源与设置样本工厂。
- `src/windows/`：正式窗口身份、请求接纳、交接与关闭协议。

### 装配

- `.github/workflows/pages.yml`：公开浏览器演示的构建、验收与 Pages 发布。
- `package.json`：预览、testbed、浏览器验收及资源测试命令。
- `vite.config.ts`：正式前端构建与测试工具的构建装配。

## 边界

- 本模块拥有浏览器测试设施，正式窗口、业务组件、服务与公共协议归各自维护者。
- 功能工作区运行正式窗口根，各嵌入页面分别持有窗口身份与状态，共用本次运行的内存样本服务。
- 固定游戏数据归 `src/test/browser/game/`，功能预览持有从文件建立的独立可编辑副本，testbed 持有自己的模拟负载。
- 聚合校对页持有所属展示样本、控件输入及操作结果，业务保存与窗口交接由正式流程交付。
- testbed 持有固定负载、预热与测量记录、对照顺序及预算判定，正式性能监视的采集与缓冲归其运行时。
- 桌面 CSV 测量由独立驱动启动所属 EXE 并注入浏览器检查代码，计时消费可视字段与后续绘制完成结果。
- 共享夹具、单元测试辅助及统计工具保持公共属性，纯后端性能样本归项目会话。
- 报告与截图归每次运行的独占输出，测试服务归独立启动入口持有，启停消费工作流授权。

## 链路

### 功能预览与验收

1. 浏览器入口读取场景登记并挂载完整测试工作区或指定聚合校对页。
2. 样本服务从固定游戏文件建立内存副本，按窗口、session 与 Mod 身份交付内容、版本、设置及事件，正式窗口消费所属流程。
3. 自动操作消费同一场景登记、就绪条件与能力，完成公开界面操作并验证结果。
4. 验收收集控制台诊断、断言及截图，报告交付实际结果与退出码。

### testbed 性能评估

1. testbed 按预览或执行请求加载所选负载，构建工具交付实际构建环境与来源哈希。
2. 测量运行器生成固定样本，独立记录预热与正式操作、耗时、资源及释放结果。
3. 对照按轮次轮换起始组，顺序采样各组，按预算计算统计与差异。
4. 输出 JSON 与 Markdown 报告，失败结果交付失败退出码。

## 规范

- 功能目录必须提供完整工作区、CSV、沉浸式编辑、字段集合、选择列表、图片文字资源及反馈浮层；正式页面快捷导航必须归工作区。
- 场景名称、入口、样本、就绪条件与支持操作必须统一登记；控件预览必须直接消费正式组件及领域规则。
- 窗口替身必须按正式身份与关闭握手交付事件，未知命令、控制台错误、警告、页面异常或断言失败必须使验收失败。
- 样本数据必须隔离于用户内容；浏览器刷新必须建立固定样本，重开窗口必须消费本次运行保存的状态。
- 固定数据必须保留取样来源的 ID、文案和图片；目录必须按资源职责组织，装配必须按主舰、战机与模块分组，总体积必须限制为 10 MiB。
- 工作区名称、版本和描述必须消费各项目 mod_info.json；势力、战役、皮肤、工业与模拟对手必须提供可解析的样本及对应图片，模拟对手必须引用已有装配。
- 保存、撤销、外部更新与样本恢复必须操作本次运行的内存副本，严禁写入固定游戏文件；数据生成脚本必须在数据定稿后删除。
- 功能工作区与 testbed 必须独立按需加载，入口之间严禁提供跳转按钮；自动检查必须连接已有服务。
- 公开演示必须复用完整工作区及内存样本，顶部只允许提供恢复样本与外观控制；全部资源、导航与嵌入窗口必须消费部署基础路径。
- Pages 必须在 main 更新或手动触发后构建并验收同一产物，验收失败必须保留报告并停止发布，发布必须按队列执行。
- 外观动作必须消费所属设置 owner，预览与受测内容必须采用同一主题与强调色；正式测量前必须释放夹具外观监听。
- 正式性能采样必须使用生产构建，开发构建结果必须注明实际环境；监视关闭对照必须采用 VITE_PERFORMANCE_MONITOR=0 与 Rust --no-default-features。
- testbed 必须默认预热 2 次、测量 30 次，预热记录必须独立；重复使用压力必须默认测量 100 次。
- testbed 项目必须限定为 CSV、武器列表、战机联队列表及插件列表，资源压力必须采用武器列表的 32、128、512 像素固定样本；筛选后无项目必须返回失败。
- CSV 基准必须采用 40 列与 50、300、2000 行，环境必须固定为 1280×720、DPR 1.5；对应中位数上限 (ms) 必须为打开 75/80/90、往返滚动 120/130/150、逐屏遍历 25/250/3000、激活 20/20/40、关闭 20/30/50。
- 武器、战机联队与插件列表必须采用 30、100、800 项样本，打开必须计至挂载后的绘制完成，资源与释放必须交付实际结果。
- 监视开关对照必须按 disabled 的 1% 或 1 ms、enabled 的 10% 或 5 ms 取较大增量上限；code 策略必须记录差异。
- 首次打开必须采用独立浏览器上下文，必须与预热后结果分别报告；统计必须包含最小、最大、平均、中位数与 nearest-rank P95，偶数中位数必须取中间两值平均。
- 桌面 CSV 测量必须核对可视字段、名称与缩略图完成，字段显示 P95 必须以 200 ms 为判定上限。
- 报告必须记录实际构建与脚本哈希、样本参数、操作顺序、浏览器、视口、DPR、缓存和监视状态，失败及释放结果必须保留。
- 每次运行必须排他持有报告与截图目录，显式输出冲突必须保留已有内容并报告实际路径。

# 浏览器预览与测试

## 定义

浏览器预览与测试模块提供隔离的浏览器预览、功能验收、testbed 性能评估及测量报告。

## 参考

### 拥有

- `scripts/browser/`：浏览器服务、构建、preview 验收、testbed 外部驱动与执行寿命。
- `src/test/browser/`：preview 功能工作区、testbed 测量场景及共同窗口、样本和运行替身。

### 消费

- `scripts/shared/`：仓库扫描、样本统计、公共报告及排他测试工作区。
- `src/app/`：正式窗口根、业务组件、主题与反馈装配。
- `src/domain/`：正式领域转换、字段定义、编辑与展示规则。
- `src/services/app-log.service.ts`：测量前等待各窗口的正式日志批次交付。
- `src/shared/`：业务协议、错误、输入与资源公共能力。
- `src/test/fixtures/`：共享领域、资源与设置样本工厂。
- `src/windows/`：正式窗口身份、请求接纳、交接与关闭协议。

### 装配

- `.github/workflows/pages.yml`：公开浏览器演示的构建、验收与 Pages 发布。
- `package.json`：预览、testbed、浏览器验收及资源测试命令。
- `tsconfig.browser-scripts.json`：浏览器驱动脚本的 Node 与 DOM 类型装配。
- `vite.config.ts`：正式前端构建与测试工具的构建装配。

### 关联

- `CONTRIBUTING.md`：浏览器测试的正式命令与参数说明。

## 边界

- 浏览器窗口启动替身交付明确的 Windows 字符映射样本，原生映射与当前系统的一致性由 Rust 验证。
- 本模块拥有浏览器测试设施，正式窗口、业务组件、服务与公共协议归各自维护者。
- 功能工作区运行正式窗口根，各嵌入页面分别持有窗口身份与状态，共用本次运行的内存样本服务。
- 固定游戏数据归 `src/test/browser/game/`，功能预览持有从文件建立的独立可编辑副本，testbed 持有自己的模拟负载。
- 聚合校对页持有所属展示样本、控件输入及操作结果，业务保存与窗口交接由正式流程交付。
- testbed 持有固定负载、预热与测量记录、对照顺序及预算判定，正式性能监视的采集与缓冲归其运行时。
- 共享夹具、单元测试辅助及统计工具保持公共属性，纯后端性能样本归项目会话。
- 报告与截图归每次运行的独占输出，测试服务归独立启动入口持有，启停消费工作流授权。
- preview 拥有功能样本、正确性与体验检查；testbed 拥有负载、规模、压力、采样及释放检查，所属执行入口持有浏览器、诊断和报告。
- 页面内场景归 `src/test/browser/testbed/cases/`，真实按键及浏览器观测归所属外部驱动，两种执行方式分别记录。

## 链路

### 功能预览与验收

1. 浏览器入口读取场景登记并挂载完整测试工作区或指定聚合校对页。
2. 样本服务从固定游戏文件建立内存副本，按窗口、session 与 Mod 身份交付内容、版本、设置及事件，正式窗口消费所属流程。
3. 自动操作消费同一场景登记、就绪条件与能力，完成公开界面操作并验证结果。
4. 验收收集控制台诊断、断言及截图，报告交付实际结果与退出码。

### testbed 性能评估

1. testbed 按预览或执行请求加载所选负载，构建工具交付实际构建环境与来源哈希。
2. 测量运行器生成固定样本，独立记录预热与正式操作、耗时、资源及释放结果。
3. 对照按轮次轮换起始组，顺序采样各组，按预算计算统计与差异。
4. 输出 JSON 与 Markdown 报告，失败结果交付失败退出码。

## 规范

- 浏览器测试尽可能复刻正式行为；本模块文档记录与正式行为的差异及测试模块自身契约。
- 浏览器 CSV 空间站数据样本必须采用标准 JSON 并消费公共输入解析；原生 CSV 空间站数据消费正式游戏 JSON 解析器，游戏扩展写法由 Rust 解析测试验收。
- 静态预览请求必须在同一处理范围内完成路径解码与文件读取；解码失败返回 400，越界路径返回 403，文件读取失败返回 404，成功读取返回 200，各分支结束响应。
- 场景名称、入口、样本、就绪条件与支持操作统一登记；控件预览直接消费正式组件及领域规则。
- 未知命令、控制台错误、警告、页面异常或断言失败必须使验收失败。
- 样本数据必须隔离于用户内容；浏览器刷新建立固定样本，重开窗口消费本次运行保存的状态。
- 固定数据必须保留取样来源的 ID、文案和图片；目录按资源职责组织，装配按主舰、战机与模块分组，总体积限制为 10 MiB。
- 保存、撤销、外部更新与样本恢复必须操作本次运行的内存副本，严禁写入固定游戏文件；数据生成脚本在数据定稿后删除。
- 功能工作区与 testbed 各自独立按需加载，自动检查连接已有服务。
- 公开演示必须复用完整工作区及内存样本，顶部只允许提供恢复样本与外观控制；全部资源、导航与嵌入窗口消费部署基础路径。
- Pages 必须在 main 更新或手动触发后构建并验收同一产物，验收失败保留报告并停止发布，发布按队列执行。
- 正式性能采样必须使用生产构建，开发构建结果注明实际环境；监视关闭对照采用 VITE_PERFORMANCE_MONITOR=0 与 Rust --no-default-features。
- testbed 必须默认预热 2 次、测量 30 次，预热记录独立；重复使用压力默认测量 100 次。
- testbed 场景统一登记名称、参数及执行入口，CSV、选择列表和两类编辑器共同消费运行、统计与报告；资源压力采用武器列表的 32、128、512 像素样本。
- 功能检查必须交付 checks，性能场景必须交付 runs，报告必须记录参数单位、操作方式、完成条件及实际采样次数，失败保留已完成样本与释放结果。
- CSV 基准必须采用 40 列与 50、300、2000 行，环境固定为 1280×720、DPR 1.5；对应中位数上限 (ms) 为打开 75/80/90、往返滚动 120/140/160、逐屏遍历 30/350/4000、激活 25/30/45、关闭 20/30/50。
- 武器、战机联队与插件列表必须采用 30、100、800 项样本，打开计至挂载后的绘制完成，资源与释放交付实际结果。
- 监视开关对照必须按 disabled 的 1% 或 1 ms、enabled 的 10% 或 5 ms 取较大增量上限；code 策略记录差异。
- 首次打开必须采用独立浏览器上下文，与预热后结果分别报告；统计包含最小、最大、平均、中位数与 nearest-rank P95，偶数中位数取中间两值平均。
- 报告必须记录实际构建与脚本哈希、样本参数、操作顺序、浏览器、视口、DPR、缓存和监视状态，失败及释放结果保留。
- 基准操作版本由构建插件唯一维护，环境记录与基准报告共同消费所属值。
- 每次运行必须排他持有报告与截图目录，显式输出冲突保留已有内容并报告实际路径。

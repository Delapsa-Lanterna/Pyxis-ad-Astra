# 文件编辑器

## 定义

文件编辑器模块在独立窗口提供已授权文本文件的编辑与错误恢复。

## 参考

`src-tauri/src/commands/file_editor.rs`：文件编辑 command 边界。
`src-tauri/src/parsers/preserve_json.rs`：文本 ID 字段范围定位与替换 owner。
`src-tauri/src/services/file_editor.rs`：后端编辑 service owner，消费 IO 路径授权并交付文本读写。
`src-tauri/src/services/project/write/entity_identity.rs`：已识别规格文本与结构化保存的身份事务 owner。
`src/app/FileEditorApp.vue`：窗口根 owner，装配唯一窗口壳与文件编辑器内容。
`src/app/FileEditorContent.vue`：窗口内容 owner，拥有行号槽、文本域、快捷键与外部文本呈现。
`src/app/composables/editors/use-file-editor-view-model.ts`：编辑 ViewModel owner，拥有文本 Draft Session、加载、保存、undo/redo 与行列聚焦。
`src/app/composables/use-dirty-window-close-guard.ts`：dirty 关闭守卫。
`src/orchestrators/file-editor-window.orchestrator.ts`：窗口打开编排 owner，处理 warning 与失败目标的窗口化。
`src/windows/file-editor.window.ts`：窗口请求 owner，承载常规与错误恢复两种请求形状。

## 边界

- 关闭守卫消费草稿、输入和保存等待，窗口请求层拥有复用与聚焦上下文。
- 后端拥有路径、父链与文本读写授权，反馈层消费结构化 location 和恢复目标。
- 常规窗口以 session、Mod 根和 path 为身份，恢复窗口消费无 session 的授权 recovery 目标。
- 恢复保存消费无 session 能力并更新实际受影响会话投影，其工具历史保持恢复模式语义。
- 文件浏览器交付内容判定后的正式打开目标，文本窗口拥有所属草稿、历史与保存。
- 文本 ViewModel 拥有 Draft Session、读取、保存、外部文本暂存和行列定位。
- 文本撤销栈归编辑会话原语，组件承载文本输入与快捷键。
- 普通文本保存作用于当前文件，已识别规格交由正式实体身份事务协调关联文件。
- 转码能力按用户选择的源编码解码，receipt 经正式提交接纳。

## 链路

### 打开常规编辑窗口

1. 业务调用点以 `sessionId + modRoot + path` 发起窗口请求。
2. 窗口请求组装身份、标题与上下文并打开 managed window。
3. 内容挂载后初始化文本 Draft Session 并加载文件文本。
4. 按目标行列滚动并聚焦文本域。

### 编辑与保存

1. 用户在文本域输入，文本 Draft Session 记录 dirty。
2. 用户点击保存或 Ctrl+S 进入保存编排。
3. 保存经 service/API 到后端校验并写盘。
4. 会话以实际提交文本和返回版本接纳基线，保留后续输入与文本历史。
5. 完整 receipt 进入统一接纳入口，按 ready 或 `pending` 处理会话投影并发送提交通知。
6. 同步失败呈现已写盘状态与同步错误，等待交接结束。

### 外部文本同步

1. 统一提交事件按实际 after 路径和快照投影当前文件文本。
2. dirty 窗口将文本暂存为外部版本并呈现提示。
3. 用户确认载入后替换文本域内容。

### 错误恢复编辑

1. 错误呈现携带结构化编辑目标时显示文件按钮。
2. 以 recovery 模式打开无 session 窗口，身份为 `modRoot + path`。
3. 保存走无 session 文件写入能力并仅写当前文件。
4. 恢复 receipt 以 nullable session 身份同步实际受影响的已登记会话，工具历史保持所属模式。

### 转码为 UTF-8

1. 反馈层在 `text.invalid_utf8` 错误且路径命中已授权会话时提供转码动作，其它错误不出现。
2. 用户选择源编码，后端按所选 GBK／GB18030 或 Windows-1252 解码。
3. 后端拒绝已有效的 UTF-8 文件，所选编码无法完整解码时报错且不写盘。
4. 解码成功经 changeset 链路写回，所属 receipt 进入统一提交接纳与窗口通知。

## 规范

- Escape 关闭必须与标题栏关闭走同一守卫语义。
- 保存期间文本域必须保持可编辑，后续文本必须按实际写盘基线计算 dirty；本地保存必须保留文本快照历史。
- 保存解析失败必须保留原文并定位行列；未完成文本跟随改名时必须保持待交接身份，文本可解析后必须接纳新路径、ID 与基线。
- 外部文本载入必须在 dirty 时确认放弃，确认必须绑定发起时的完整目标；接纳后必须清理文本历史。
- 外部读取、重置与关闭必须消费同一保存等待能力；外部载入或重置必须按目标上下文清理历史。
- 已识别规格读取必须共同返回文本、正式 `EntityEditInfo` 与所属版本范围；文本修改 ID 必须消费结构化保存的同一身份事务。
- 恢复入口只允许消费后端结构化 recovery 目标；恢复保存只允许写当前文件，必须使用无 session 能力，严禁登记文件历史。
- 撤销重做必须在文本域获得焦点时仍然生效。
- 文件读取和保存必须消费 IO 规范路径识别所属实体；保存必须消费正式读取交付的版本凭据并由事务核对。
- 文件路径、窗口上下文、原生登记、事件过滤与保存句柄必须共同消费当前目标；后续编辑必须按实际写盘文本计算 dirty。
- 文本事务必须保留提交原文；身份字段归一与外部跟随只允许修改解析定位的 ID 值范围。
- 文本域必须完整保留换行与空白，严禁规范化输入内容；转码必须按用户选择的源编码执行，严禁自动探测。
- 文本窗口必须登记所属文件及实体关联的版本范围；联合准备必须消费原文输入、保存等待与正式文本保存，错误必须保留原文。
- 本地编辑、保存与基线交接必须使较早读取的值与错误失效；文本、目标和版本必须共同接纳。
- 浏览入口必须消费已授权的完整窗口目标；窗口复用必须保留已有文本草稿、历史与 dirty 状态。
- 窗口复用必须经正式请求接纳最新行列与诊断，文本、历史和 dirty 必须继续由原文本会话拥有。
- 行号槽必须与文本域滚动同步，目标行高亮并支持列定位。
- 错误恢复窗口必须以 nullable session 身份发布完整提交结果；恢复入口必须消费后端返回的实际关联会话集合。

## 陷阱

- 从错误消息文本解析授权根目录会让恢复窗口写越权目标。
- 回放文本直接覆盖文本域会让未保存输入丢失。
- 把外部暂存文本当作已保存内容会让 dirty 状态与磁盘状态混淆。
- 把恢复保存当作常规 session 保存广播会让通知缺少所属身份。
- 行号槽与文本域滚动不同步会让行列定位失准。

# 编辑会话原语

## 定义

编辑会话原语模块管理目标草稿、基线、输入、历史和未保存工作。

## 边界

- JSON 原文解析、形状校验与格式化归共享纯模块，会话消费提交结果。
- 保存 owner 返回实际内容和版本，会话在同一快照动作中映射目标、基线和后续草稿。
- 外部快照由会话直接接纳或暂存，确认与取消由所属交接动作完成。
- 快照历史绑定 `EditContext`，消费方负责业务身份映射与响应式容量输入。
- 控件必须提供无写入的校验结果，FieldInputs 必须交付原文错误及所属文档问题；文档完整性检查必须独立于控件挂载，目标释放必须清理所属登记。
- 控件拥有原文与转换错误，领域拥有字段形状和转换，`FieldInputs` 拥有提交顺序与接纳权。
- 未保存注册表按 Mod 根聚合会话和 CSV 判定源，导航与关闭消费其判定入口。
- 编辑会话原语持有完整目标快照、base、draft、revision、dirty 与 `pending` external。
- 适配器提供 Ref API，目标会话接纳读取结果、保存句柄及实际持久化基线。

## 链路

### 文档目标编辑

1. 所属运行态为正式文档持有 Draft Session，ViewModel 展示选定会话。
2. 视图显式注入会话返回的 FieldInputs；表单双向赋值经适配器 setter 提交原语 draft，适配器投影 dirty。
3. 延迟提交控件登记原始输入，输入差异进入所属会话 dirty。
4. 主窗口存活期间按 `modRoot` 在注册表登记 dirty。
5. 保存先逐项提交输入，再捕获独立草稿与版本凭据。
6. 保存成功后以返回实体提交 base；请求期间的新草稿与原始输入保留。

### 外部更新接入

1. 外部读取通过所属通道捕获目标与 `ReadTicket`。
2. 接纳边界复核票据、提交身份与当前目标。
3. 无 dirty 时直接采用新 base。
4. 有 dirty 时外部版本仅暂存并提示可载入。
5. 用户确认放弃后替换 draft、取消所属原始输入并清除暂存。

### 未保存判定

1. 导航等待所属保存句柄并提交当前活动输入。
2. 页面导航交接活动身份，所属缓存与 store 保留草稿及历史。
3. 移除 Mod 或关闭工作区等待保存，随后查询最新未保存状态。
4. 注册表聚合 JSON 会话登记与 CSV 判定源，并向关闭保护交付实际 dirty。
5. 确认放弃后释放所属会话登记并继续销毁。

### 文本撤销栈

1. 文件编辑器以原语家族的撤销栈承载文本前后值。
2. undo/redo 通过栈操作返回目标文本。

## 规范

- CSV、JSON、规格及文本文件保存必须进入所属项目队列；各会话必须独立维护草稿及草稿撤销重做。
- dirty 派生必须由原语内部比较产生，严禁外部手工置位。
- 业务字典快照必须采用无原型对象保留全部自有 JSON 键；字段展示必须消费正式 JSON 格式化，严禁将原型属性作为业务值。
- 交接必须等待所属保存完成；成功后必须重新判定最新 dirty，取消或失败必须结束当前交接意图并保留编辑面。
- 保存准备必须保留基线已有路径的读取凭据；新建或改名的独立目标必须追加目标凭据，同一物理文件的大小写变化必须消费原凭据。
- 保存准备必须在所属会话持有保存状态后执行；关联表的新版本只允许更新关联凭据，规格值与规格凭据必须保持同一读取来源。
- 保存取消只允许结束所属请求，项目登记或恢复失败必须保留当前工作及后续队列，其他项目必须独立推进。
- 保存句柄必须登记进行中保存；导航和关闭必须等待项目保存及恢复结果，再判定最新 dirty。
- 保存动作必须覆盖输入准备、独立捕获与项目执行结果；同文档进行中请求必须复用唯一保存结果，内容接纳必须归所属消费过程。
- 保存期间刷新必须合并为一次后续权威读取；同值同版本刷新只允许原子更新元数据，值或版本变化必须推进基线代次。
- 保存注册表必须直接消费编辑参与者的已有草稿和输入集合，关闭捕获必须共同核对登记身份、目标、业务值、dirty 与输入生命周期。
- 保存登记必须提供实际写入范围、原 dirty、输入提交、所属保存和等待能力。
- 保存请求必须捕获点击时的目标、活动输入和实际修改，确认必须消费捕获内容，后续草稿操作必须独立保留。
- 再次保存必须捕获当前输入与草稿，内容读取失败必须交给所属内容待办继续处理。
- 原始输入提交必须按登记顺序执行，每项成功后必须等待消费者投影；失败必须保留原文、定位字段并以 `commit-field-inputs` 动作上抛一次错误。
- 写入失败必须由所属会话映射呈现结果并保留原始错误链与动作；内容处理失败必须由所属项目同步待办报告，所有保存入口必须消费同一会话检查与确认。
- 内容接纳失败必须由项目同步保留尚未完成步骤；重试必须继续所属内容步骤。
- 字段删除只允许取消对应稳定身份的输入子树；明确基线替换必须取消所属集合输入。
- 已写盘接纳必须沿正式消费顺序完成身份、基线和必要读取；保存成功反馈必须消费项目执行结果。
- 异步字段与资源选择必须捕获所属输入或编辑上下文；外部基线、目标交接与释放必须撤销其结果和错误接纳权，本地保存必须保留编辑连续性。
- 快照历史释放必须撤销容量与上下文监听；目标、外部基线及保存交接必须继续消费所属历史生命周期。
- 快照接纳必须区分 `baseline`、`pending` 与 `obsolete`，保存只允许消费 `ready` 目标。
- 撤销栈 limit 必须由消费方显式提供；快照历史必须消费响应式 `editHistoryLimit`，容量变化必须立即裁剪最早的 undo 并保留 redo，领域原语只允许消费所属容量值。
- 文档动作必须共同交付完整目标、输入、dirty、保存状态、保存与等待、历史能力及撤销重做结果；保存成功必须携带正式回执。
- 未完成字段输入必须参与 dirty、关闭确认和外部版本暂存；本地提交、保存、明确基线交接与释放必须撤销较早读取的值、错误与 loading 接纳权。
- 本地保存必须保留同一会话历史；目标加载、外部基线接纳与重置必须共同清理历史、活动动作、选择和预览。
- 注入的相等比较与克隆必须覆盖全部业务值形态；目标快照的业务值、目标元数据和版本凭据在同一装配边界分别取得独立副本。
- 注册表严禁暴露内部会话结构，只暴露按 `modRoot` 的判定与登记能力。
- 目标、业务值、版本和元数据必须通过同一响应式快照发布；身份交接必须原子接纳基线并映射草稿，dirty 外部快照必须暂存。
- 目标必须捕获 `sessionId`、`modRoot`、实体种类、ID 与实际路径；保存必须消费捕获目标，重命名必须在同一会话交接目标并保留后续输入。
- 目标重叠必须由编辑会话领域规则比较相同 session、规范化 Mod 根及双向目录包含关系；保存注册与目标交接必须消费同一入口。
- 自有身份事务推进基线时必须保留编辑连续性；外部身份交接必须按正式身份映射快照历史并保留确认后的草稿与活动输入。
- 草稿只允许保存在所属编辑会话内，严禁直接持久化、query 或 write；对外判定必须消费未保存注册表。
- 表单双向绑定必须经唯一适配器 setter 提交 draft，严禁直接替换投影状态或以深度 watch 同步业务副作用。
- 输入取消、目标变化与集合释放必须撤销当前提交接纳权；卸载必须解除登记，销毁会话必须释放集合与目标身份。

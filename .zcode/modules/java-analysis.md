# Java 分析

## 定义

Java 分析模块管理 Java 17 语法与语义分析、固定第三方依赖、自有宿主及分析实例的资源寿命。

## 边界

- 应用适配消费正式配置根，独立库维护 java-analysis 子目录中的依赖、工作区与日志。
- 应用初始化只持有目录描述、固定资源和空实例集合，实际操作按明确调用执行。
- Java 语言语义由 JDT 维护，Rust 拥有安装、进程、请求和释放。
- 项目来源以显式源码根、类路径和目标标准库交付，内存修改归 WorkingCopy。
- 依赖包采用固定的 Maven 地址、大小和 SHA-256，自有 Java 宿主随应用资源交付。
- 语法、类型和引用查询按项目分析快照交付，实例之间独立持有私有 JDT 源码资源。
- 项目文件集合由调用方按版本提交新增、替换、删除和移动，分析模块不写入来源目录。
- 应用日志消费操作身份和状态，Java 原始诊断留在所属实例日志。
- 显式分析按 Mod 会话创建项目，已启动会话共用一个 JVM，最后项目关闭后释放 JVM。
- 代码窗口在首次打开分析源码根内的 Java 文件后启动所属项目，空窗口和普通文本保留惰性状态。
- 全部已发布可引用 Mod 按工作区顺序参与 Java 输入，引用自动刷新保留当前内存文档。
- 组件管理任务由后端独占持有，页面只订阅状态；取消完成后保留已校验文件供重试。
- 环境自检使用所属短时 JVM，完成进程和读取线程等待后释放工作区。
- 手动 Java 路径通过完整设置快照保存、镜像及重置，并对下次会话启动和自检生效。
- 代码窗口身份由命令边界交付，草稿更新限定所属 Mod，引用源码读取限定分析项目的实际来源。

## 链路

### 初始化与安装

1. 应用启动经正式配置根创建并登记 Java 分析运行态。
2. 安装调用按依赖集标识取得文件锁，逐个下载或导入已固定的第三方 JAR。
3. 文件核验完成后登记完整依赖清单，后续启动消费同一集合。

### 分析与释放

1. 启动调用接纳实际 Java 路径，创建所属实例目录和日志。
2. Rust 交付内置宿主及已安装依赖，等待 Java 17 协议握手。
3. 语法或项目请求进入 JDT，结果保留请求身份、文档版本和源码范围。
4. 实例关闭等待 JVM 与读取线程结束后清理工作区并保留日志。
5. 应用确认关闭后停止新工作并等待全部所属实例释放。

### 组件管理

1. 主窗口向设置页固定槽位交付卡片与当前会话及游戏根，卡片订阅后端正式状态。
2. 用户动作取得唯一管理任务，下载和导入逐文件校验并共同发布完整安装。
3. 状态订阅交付进度及一次最终回执，页面释放订阅后后台继续持有任务。
4. Java 路径选择先验证版本再提交设置，自检独占短时 JVM 并等待所属资源释放。
5. 停止动作释放全部分析，移除动作清理所属依赖和暂存，应用关闭先取消并等待管理任务。

### 编辑交接

1. 文件快照与输入完成状态进入所属 Java 会话，范围修改合并后顺序提交。
2. 正式会话填入项目修订，JDT 交付带文件版本的语义结果及修改方案。
3. 前端按当前内容与路径接纳结果，扩展绘制诊断、悬停、补全和参数提示。
4. 大纲与结果面板交付定位，修改方案经窗口装配交给文本文件编辑核对及接纳。

## 规范

- 最低 Java 开发及运行基线为 17，自有资源构建与第三方字节码按该基线验收。
- 配置根必须消费正式工具目录，依赖、工作区和日志必须归模块专属子目录。
- 依赖集标识必须共同表达 JDT 版本与固定文件清单哈希。
- 协议、自有宿主、Java 运行要求、默认语言与 JDT 版本必须由 `src-tauri/java-analysis/versions.json` 唯一维护；Rust 常量、Java 配置与打包清单共同消费该声明。
- JDT 锁定记录中的版本占位符必须由构建入口解析，实际依赖继续按固定大小及 SHA-256 校验；格式化器版本与校验和归检查入口共同维护。
- 自有宿主、依赖清单和实际文件必须在启动前核对匹配关系。
- 源码范围必须采用 UTF-16 半开区间，节点与绑定结果必须绑定所属项目及分析版本。
- 前端排队查询必须绑定捕获的文字、路径和位置，等待后及结果发布前复核所属文件寿命。
- 只读引用标签关闭必须结束所属投影持有，输入等待结束后只允许提交仍登记的文件。
- 同一分析版本必须复用已建立的 AST，更新必须推进版本并失效所属结果。
- 文件和 JAR 变化必须按声明、使用及反向影响范围失效，无法确定范围时交付完整重建原因。
- 同版本引用位置复用按文件维护的绑定索引，变更只替换受影响文件的索引条目。
- Rust 请求与结果必须消费模块协议类型，进程边界必须核对请求编号、操作和结果类型。
- 项目释放必须共同丢弃工作副本、AST、引用索引和实例内源码资源。
- 文档诊断与大纲随文件分析快照复用；同项目版本的窗口刷新复用后台文件投影。
- 文件变化批次必须先核对项目版本、文件版本及路径归属，再共同更新项目文件集合和工作副本。
- 依赖、语言级别及标准库变化必须推进项目版本，并使 AST 与声明引用索引失效。
- 声明和引用位置按绑定身份建立项目版本索引，同版本查询复用该索引。
- 正常释放必须等待进程和读取线程结束，再清理实例工作区；依赖与原始日志保持各自寿命。
- 共享 JVM 的启动和末项目释放由生命周期互斥协调，项目登记锁只保护句柄取得与登记；项目释放失败仍须完成末实例释放。
- 应用路径适配接纳请求所有权，进程管道直接序列化类型化请求并按实例缓冲写入。
- 应用操作日志只允许包含身份、路径、状态、规模及诊断，严禁记录源码正文和请求响应正文。
- 请求详细记录包含项目、用途、排队、往返耗时及响应字节；项目和组件完成事实使用 INFO，依赖缺失及引擎拒绝使用 WARNING，传输与管理操作失败使用 ERROR。
- 组件管理动作必须经单一 FIFO 队列执行，相同动作复用队列项，操作键只表达队列项身份并关联其取消控制。
- 依赖变更必须在队列执行时核对全部分析实例已释放；队列存在待办时禁止新建分析实例。
- 取消必须结束所属网络请求后交付回执，已校验文件保持可复用，未完成文件必须保留独立暂存身份。
- 库、开发检查工具与组件管理共用安装和暂存移除入口，并取得所属依赖集的安装锁。
- 管理卡片位于配置文件与性能调试之间，停止与移除通过危险确认并说明实际影响。
- 编辑器更新与引用刷新必须持有同一项目版本锁；悬停、声明、引用和大纲必须复用所属 AST 与绑定索引。
- 补全与参数查询消费当前 WorkingCopy，导入及重命名只交付带版本的范围修改；重载选择变化必须在接纳前复核。

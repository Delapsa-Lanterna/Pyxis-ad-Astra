# 文本与格式解析器

## 定义

文本与格式解析器模块提供 Starsector CSV-like 与 JSON-like 的解析和渲染。

## 参考

### 拥有

- `src-tauri/src/domain/document_edit.rs`：完整精确内容、源对应关系及局部结构编辑的纯规则。
- `src-tauri/src/parsers/`：游戏格式公开入口、JSON/CSV 解析与局部渲染、索引、字段资产及工具 JSON 读取。
- `src-tauri/src/parsers/json_writer.rs`：JSON 原结构和展开写出，消费完整值、源位置及已解析目标格式。
- `src-tauri/testdata/`：游戏 CSV 与 JSON-like 解析夹具。

### 消费

- `src-tauri/src/models/file_content.rs`：精确文档、布局、完整写入请求及结构编辑协议。
- `src-tauri/src/models/file_value.rs`：64 位整数、浮点与 UTF-16 文字的精确表示。

### 关联

- `src-tauri/src/io/csv_files.rs`：消费格式读取入口，绑定 CSV 文件路径与版本。
- `src-tauri/src/io/json_files.rs`：消费格式读取及写出能力，绑定 JSON 文件路径与版本。
- `src-tauri/src/io/text.rs`：消费纯文本解码能力，绑定明确源编码及文件路径。
- `src-tauri/src/services/project/write/config_entity.rs`：Mod 信息与战役目录保存的格式消费者。
- `src-tauri/src/services/project/write/entity_write/single_files.rs`：装配与皮肤文件保存的格式消费者。
- `src-tauri/src/services/spec_editor.rs`：外部规格导入的格式消费者。

## 边界

- 格式模块维护原版读取语法、精确值、原始格式及源位置。
- 公共模型交付 i64 整数、f64 浮点、UTF-16 文字、对象顺序和物理 CSV 行格。
- 游戏 JSON/CSV 读取统一从 parsers::game 进入，精确数据与布局类型从公共模型导入。
- CSV 内容读取与完整文档共用解析过程，内容读取省去布局构建，完整文档保留位置资料。
- schema 维护业务转换、校验和修改位点的目标格式。
- 写出器消费完整数据、源对应关系和目标格式，生成原结构或展开布局。
- 布局建立复用所属来源的精确值，写出过程借用同次来源内容及位置；连续词元可直接引用共享源文本。
- IO 维护授权字节、版本、实际落盘及字节回放，编辑会话维护修改、历史和实际结果接纳。
- 读取错误携带完整解码原文及原始位置，IO 为诊断绑定文件路径。

## 链路

### 结构化读取

1. IO 交付同次源字节和文件版本。
2. 游戏解码跳过 UTF-8 BOM，按 Java 替代规则处理损坏字节。
3. JSON 入口应用原版注释与取词规则，CSV 入口按物理记录读取表头、行格、注释与空行。
4. 同一过程交付精确数据，并按用途建立布局位置。
5. 来源及编辑会话保留完整基线，上层按需要形成业务投影。

### 局部写出

1. 调用方交付完整目标数据、各成员与源位置的对应关系及目标格式。
2. 未修改值复用源写法，修改和新增值按声明生成。
3. 原结构模式保留布局，展开模式组织展开 JSON 或简单 CSV。
4. 增删及重排处理必要分隔符、局部样式及固定位置的注释。
5. 输出在内存中重读核对精确内容和顺序，交给 IO 形成变更集。
6. 实际输出的数据、格式与版本成为编辑会话的新基线。

### 纯文本读写

1. 文本读取严格解码 UTF-8，明确指定其它源编码时按该编码解码完整输入。
2. 调用方提交完整文本，IO 写出 UTF-8。
3. 后续格式读取按相应文件类型交付内容或诊断。

## 规范

- JSON-like 读取必须采用游戏实际的注释、键值、分隔符、数组空槽和根对象尾文规则。
- 无引号 word 必须按原版分支读取：1f 为文字，0.1f 为浮点；整数越界后采用原版文字结果。
- 对象值的非有限数字必须按原版报错，数组值按原版保留无穷大。
- JSON 精确内容必须保留整数、浮点、文字类型以及完整 UTF-16 单元，对象成员保持读取顺序。
- 复合键必须生成原版实际文字键，写出按已生成键名表达其语义。
- JSON 错误必须保留原始位置，行列采用原文及 UTF-16 列位置。
- BOM 跳过与超过 1 MiB 的完整多字节读取必须作为明确兼容要求执行。
- CSV 必须保留重复表头、缺失格、额外格、注释、空行和原始换行的物理位置。
- CSV 的业务列投影必须按原版表头与有效格规则形成，物理文档保留完整读取内容。
- 两种结构化保存必须保留全部未修改值的源写法，生成格式只作用于修改和新增位点。
- 原结构保存必须保留空格、Tab、换行、相对结构与注释位置；明确编辑仅改变操作所需的局部结构。
- 新增内容必须采用所在容器的局部样式，行尾注释固定在布局位置。
- 展开 JSON 必须采用展开布局，简单 CSV 必须保留注释和空行语义。
- 写出结果必须重读核对完整精确内容和成员顺序，表达失败交付具体位置与原因。
- 结构化文本必须使用游戏替代解码并输出 UTF-8，纯文本必须使用严格 UTF-8 或明确源编码。
- 纯文本保存必须完整表达提交文本，语法错误由后续格式读取交付诊断。

# 浏览器游戏数据

## 结构

仓库目录按游戏目录结构保存为 `starsector-core/`(伪原版 Core) 与 `mods/<Mod 目录名>/`(示例 MOD)。

## 素材权利

样本取自 Starsector 0.98a-RC8、Kratogen_TA、Polaris_Prime 和 ICE。游戏及 Mod 的图片、文字和数据等素材权利归各自原持有者；项目代码许可适用于本项目代码，素材的使用与分发必须遵守原持有者的许可条件。

## 取样要求

- Core 基础样本以 6 艘主舰、12 种武器、3 种战机联队和 8 种船体插件为目标。
- 每个 Mod 基础样本以 3 艘主舰、6 种武器、1 种战机联队和 3 种船体插件为目标。
- Core 必须提供 3 个势力、2 个战役、3 个具有样本基础船体的皮肤和 3 个模拟对手；每个 Mod 必须从已有装配中选择 2 个模拟对手。
- 上述数量是取样起点，不是依赖闭包的数量上限。装配、舰载机、模块、皮肤、内置装备、武器、弹体、系统、说明、配置及其资源引用所需文件必须一并纳入。
- Mod 保留来源中实际存在的内容类别与类别分布；来源没有的表格保持缺失，不得用重复或虚构行填充。
- 数据集总大小必须不超过 10 MiB。

## 内容与资源

- 舰船、武器、战机、插件及配置保留来源 ID、名称、说明文案和字段值；文件之间的 ID 引用必须保持一致。
- PNG 图片采用来源原图，保持对应规格引用与相对路径可解析。目录按游戏资源类别组织，装配按主舰、战机和模块归类；不得生成替代 SVG 图。
- 所有纳入数据集的 OGG 文件必须替换为同一个单声道、约 0.01 秒、单音频帧的静音 Vorbis 文件；原文件名、目录和声音注册关系必须保留。
- 势力必须分别采用来源 logo 与 crest；战役必须保留来源图标、描述和正文，MissionDefinition 必须采用包含 `// not implemented` 的占位实现；工业必须保留 image 引用及图片文件。
- 来源数据目录只读。临时转换或整理程序不得作为数据集内容保留。

## 处理流程

1. 从对应来源目录只读选取基础实体和表格行，并保留来源 ID 与文案。
2. 沿装配与实体引用逐层补齐船体、皮肤、模块、战机联队、装备、弹体、系统、说明、配置和图片，直到引用闭合。
3. 按游戏相对目录放置 Core 与三个独立 Mod；Core 声音注册表只纳入所选规格使用的 ID，并将所有已纳入 OGG 替换为统一静音占位文件。
4. 核对规格引用、CSV ID、装配槽位、图片路径和声音注册路径均能在所属 Mod 或 Core 中解析，并复核总大小上限。
5. 浏览器从固定文件建立本次运行的内存副本。编辑、保存、撤销、重开和恢复样本只作用于该副本，不得写回固定文件。
6. 需要确认游戏加载时，将样本放入独立验证目录，使用对应版本的完整游戏安装手动启动并进入游戏；不得改动用户安装目录、Mod 启用配置或存档。
